## PR #7 — 온보딩

**증상.** 전체 feature e2e 가 오래된 선택자와 개발 DB 상태에 따라 깨져 배포 게이트 역할을 못 했다.

**원인.** 테스트가 개발자가 쓰는 DB · 3000 번 서버에 붙어 돌았다. 데이터가 바뀌면 결과가 바뀌고, 시드를 넣으면 개발 DB 를 덮는다.

**해결.** `npm run test:e2e:local` — 랜덤 이름 `omnis_e2e_*` DB 를 새로 만들어 마이그레이션 · 데모 시드를 넣고 임시 앱 복사본을 3002 에서 띄운다. 원격 DB 주소면 거부한다. 45개 통과.

**다음에.** 시드를 넣는 테스트는 **새로 만든 DB** 에만 돌린다. 절차: [manual/e2e-local.md](../manual/e2e-local.md)

## PR #8 — 옴니스 답변 렌더

**증상.** 옴니스 AI 답변 · 주간보고 · 지식 카드가 목록 글머리 · 들여쓰기 · 제목 크기 없이 굵은 글씨만 줄줄이 보였다.

**원인.** `prose prose-sm` 을 썼는데 `@tailwindcss/typography` 가 설치돼 있지 않았다. 클래스는 오류 없이 **아무 일도 하지 않고**, Tailwind 초기화 스타일이 그대로 남는다.

**해결.** `globals.css` 에 `.omnis-md`(components 레이어)를 두고 4곳에 적용. 각주 `[11, 12]` 배지, 출원번호 줄바꿈 방지, 줄바꿈 한 번을 hard break 로.

**다음에.** 유틸리티 클래스가 "먹는지" 는 브라우저 계산 스타일로 확인한다. 플러그인이 필요한 클래스(`prose`, `line-clamp` 구버전 등)는 `package.json` 부터 본다.

## PR #9 — 스레드 첨부·멘션

**증상 1.** 채팅에서 **완료된 업무**를 `#멘션` 하면 업무가 '진행 중' 으로 돌아갔다.

**원인.** `lib/chat-post` 의 AI 재구성이 "보고 · 피드백은 진행 중 신호" 라며 `status !== IN_PROGRESS` 면 진행 중으로 전진시켰다. 완료 업무를 가리키기만 한 글도 그 규칙을 탔다.

**해결.** 채팅에서 완료 업무를 멘션한 것은 **참조만**(메시지 · 파일 연결, 재구성 · 상태 변경 · 알림 없음). 완료 업무의 스레드에 직접 쓴 글은 예전처럼.

**증상 2.** 스레드 안에서 다른 업무를 `#멘션` 하면 메시지가 그 업무로 옮겨 가 재구성됐다.

**해결.** 스레드 연결(`taskId`)이 `#멘션` 보다 먼저다. 스레드 안의 멘션은 참조다.

**다음에.** 상태를 바꾸는 규칙은 **어느 입력이 그 규칙을 타는지** 전부 적어 본다 — "완료된 업무에 대한 글" 처럼 규칙을 만든 사람이 떠올리지 않은 입력이 있다.

## PR #10 — MCP 이름·시스템 계정

**증상.** 허채정 지시 · 정우창 수행 업무에 「담당자 확인을 기다립니다」 가 **김아리** 이름으로 찍혔다.

**원인.** 🤖 메시지 작성자를 `HADD MCP` 계정 → 없으면 **정렬 없는 첫 ADMIN** 으로 골랐다. 그 계정은 어느 DB 에도 없었고, 정렬이 없으니 같은 코드가 09-08 에는 허채정, 09-10 에는 김아리를 골랐다.

**해결.** 시스템 계정 `system`/`Omnis` 를 코드가 upsert(비활성 · 로그인 불가). 기존 메시지는 `scripts/backfill-system-author.ts`.
비활성으로 두면 어디서나 숨는다고 봤지만 `isActive` 를 거르지 않는 조회가 두 곳 있었다 — AI 담당자 후보(`app/api/ai/structure-task`)와
`list_members(includeInactive)`. 둘 다 `id: { not: SYSTEM_USER_ID }` 로 뺐다.

**다음에.** "없으면 아무거나" 로 고르는 `findFirst` 에는 정렬이 있어야 하고, 대개는 고르지 말고 전용 계정을 둔다.
숨기려는 계정을 추가하면 `user.findMany` 를 전부 grep 해 거르는 조건을 확인한다.

### 같은 PR 에서 밟은 것

**1. 주소는 그대로 둔다.** MCP 서버 이름은 바꿨지만 주소(`/api/ip-mcp`)는 뒀다 — OAuth issuer 와 resource 식별자가 주소라 바꾸면 붙어 있는 커넥터가 전부 끊긴다.

**2. 커넥터 이름은 서버가 아니라 사람이 적은 값이다.** claude.ai 에 「HADD IP」 로 보인 것은 커넥터를 추가할 때 적은 이름이었고, 그 커넥터는
옛 Supabase 함수 주소를 가리켜 410 을 받고 있었다. 410 안내 문구도 한 도메인 이전 **전** 주소(`omnis-hadd.vercel.app/api/ip-mcp`)를
알려줘, 따라가도 붙지 않는다.
→ 서버 이름을 바꿔도 사용자가 커넥터를 지우고 다시 추가해야 보인다. 안내 문구에 주소를 박아 두면 주소를 옮길 때 같이 고친다.

**3. 추론된 유니온 반환 타입은 `"error" in r` 로 좁혀지지 않는다.** 업무 수정 알맹이를 `lib/task-update.updateTask` 로 옮겨
`{ error }` 또는 `{ task }` 를 돌려주게 하자, 라우트의 `apiError(400, result.error)` 에서 TS2345(`string | undefined`).
반환 타입을 적지 않으면 TypeScript 가 `{ error: string; task?: undefined } | { task: …; error?: undefined }` 로 정규화해
`in` 검사가 양쪽을 다 통과시킨다. MCP 쪽 `if ("error" in r) return r` 도 같은 이유로 `ToolResult` 에 맞지 않았다.
→ lib 함수가 성공 · 실패 유니온을 돌려주면 반환 타입을 적는다(`Promise<{ error: string } | { task: UpdatedTask }>`).

**4. Gemini 가 죽어 있을 때만 통과하는 검증이 있었다.** 첫 검증에서 `verify-omnis-mcp` 3건이 Gemini 월 지출 한도 429(PR #11 의 3번과 같은 원인)로
실패해 환경 탓으로 넘겼다. 한도가 풀리자 앞 단계 `post_message` 가 **실제 AI 재구성**으로 검증용 업무의 체크리스트를 바꿔 놓았고,
뒤의 체크리스트 검증 2건이 가정한 초기 목록과 달라져 실패했다(도구는 「아무것도 바꾸지 않았습니다」로 맞게 응답했다).
→ AI 가 상태를 바꿀 수 있는 단계 뒤의 검증은 상태를 직접 되돌리고 시작한다. 외부 API 가 죽은 채로 나온 결과는 통과로 치지 않고, 살아 있을 때 한 번 더 돌린다.

**5. 작업 중에 main 이 같은 파일을 바꿨다.** 다른 세션의 PR #9 가 `lib/chat-post.ts` 를 고쳐 먼저 머지됐다. 충돌은 없었지만
rebase 뒤 다시 돌린 검증에서 4번이 드러났다.
→ push 직전에 `git fetch` 로 main 을 보고, 움직였으면 rebase 뒤 verify · build · 검증 스크립트를 **전부** 다시 돌린다.

**6. 다른 세션이 쓰는 폴더에서는 브랜치를 바꾸지 않는다.** omnis-local 이 다른 세션의 브랜치에 있어 `git worktree add -b feat/mcp-hadd-omnis ../omnis-mcp origin/main`
으로 따로 열었다. `npm ci`(PR #14 의 심볼릭 링크 함정), DB 는 컨테이너 안에서 `pg_dump omnis | psql omnis_mcp` 로 복제,
`.env` 만 복사해 DB 이름과 `NEXTAUTH_URL` 포트(3100)를 바꿨다. `.env.production.local` 은 복사하지 않는다(PR #13).

**7. `gh pr merge --match-head-commit` 은 40자 SHA 만 받는다.** 짧은 SHA 는
`Could not coerce value "2cad6e2cad" to GitObjectID` 로 거부되고 PR 은 열린 채 남는다.
→ `--match-head-commit "$(git rev-parse HEAD)"`. 머지 뒤 `gh pr view --json state,mergeCommit` 으로 실제로 머지됐는지 본다.

**8. zsh 에는 `PIPESTATUS` 가 없다.** 이 맥의 셸은 zsh 다. `npx tsc | tail; echo ${PIPESTATUS[0]}` 가 빈 값을 찍어 종료 코드를 잃었다
(bash 전용 변수, zsh 는 소문자 `pipestatus`).
→ 출력을 파일로 보내고 `$?` 를 본 뒤 파일을 읽는다.

## PR #11 — 회사 Context

**1. 마이그레이션은 배포가 돌리지 않는다.** Vercel 빌드는 `prisma generate && next build` 뿐이다. 새 표를 읽는 코드가 먼저 배포되면 첫 화면이 없는 표를 읽다 오류가 난다.
→ **운영 DB 에 `prisma migrate deploy` 먼저, 머지 나중.** 적용 전 SQL 에서 데이터를 지우는 구문 · NOT NULL 추가를 확인한다.

**2. pdf.js 가 넘긴 버퍼를 떼어 간다.** 세금계산서 PDF 를 글자로 읽은 뒤 같은 버퍼를 AI 판독(vision)에 넘기자 Gemini 가 400 을 돌려줬다. `getDocumentProxy(data)` 가 `ArrayBuffer` 를 transfer 해 원본이 비었다.
→ `getDocumentProxy(data.slice())` 로 사본을 넘긴다.

**3. Gemini 429 는 분당 한도가 아닐 수 있다.** 회사 질문 평가가 429 로 멈췄는데 재시도로 풀리지 않았다 — AI Studio **월 지출 한도** 초과였다. 작업지시자가 한도를 올린 뒤 재실행.
→ 429 본문의 사유를 읽는다. 월 한도면 기다려도 안 풀린다.

## PR #12 — 화면 배율과 떠 있는 창

**증상.** 운영에서 알림 창이 오른쪽으로 잘렸다. 1920px 에서 177px 넘침, 채팅 + 메뉴는 버튼에서 152px 떨어져 화면 아래로.

**원인.** `html` 에 `zoom: 1.1`(데스크톱 배율)을 거는데, base-ui(floating-ui)는 트리거 위치를 **화면 px** 로 재고 그 값을 **zoom 이 걸린 좌표계** 의 translate 로 쓴다. 창이 zoom 배만큼 밀린다. 셀렉트는 선택 항목을 트리거에 겹쳐 놓는 다른 방식이라 멀쩡했다.

**해결.** 위치 칸(Positioner)을 `scale: 1/zoom` 으로 줄이고 안의 창에 `zoom` 을 다시 건다. scale 은 레이아웃을 바꾸지 않아 위치 계산에 되먹임이 없다.

**버린 시도.** `positionMethod="fixed"`(더 넘침), 위치 칸에 zoom 역보정(뒤집기 계산이 깨져 창이 화면 위로 감).

**다음에.** CSS `zoom` 을 쓰는 한 떠 있는 UI 라이브러리를 새로 들일 때마다 1920 · 1440 · 1024 · 390px 에서 트리거와 창의 x 차이를 잰다.

## PR #13 — 서명·직인 보관

**사고.** 서명 교체 기능을 이 맥에서 `next start -p 3001` 로 점검했더니 **운영 DB** 에 서명 교체 · 직인 등록 · 활동 기록 2건(관리자 계정)이 들어갔다. 파일은 로컬 `_dev` 폴더에 가 있다가 정리로 지워져, 잠시 운영에서 정우창 서명이 열리지 않았다.

**원인.** `next start` · `next build` 는 **`.env.production.local`** 을 읽는다. omnis-local 의 그 파일에는 운영 Neon 주소가 있다. `next dev` 는 읽지 않는다.

**복구.** 운영 원본 파일은 그대로였다(md5 일치). 직전 스냅샷 값으로 원래 행을 되살리고 테스트 행 · 기록을 지운 뒤, 서명 5장 · 최근 기록 0 을 확인.

**다음에.**
- 로컬 점검은 `next dev` 로만. 운영 빌드를 로컬에서 띄워야 하면 DB 환경변수를 **로컬로 직접 지정**하고, 로컬에만 있는 표식이 화면에 보이는 것을 확인한 뒤에 쓴다.
- 점검용 작업 폴더(worktree)에는 `.env*` 가 없는지 먼저 본다 — 없으면 운영 주소를 읽을 방법이 없다.

**곁가지 함정.**
- Synology WebDAV `PROPFIND Depth: infinity` 는 403. 폴더를 훑으려면 `Depth: 1` 로 내려간다.
- NAS rclone 마운트는 폴더 목록을 캐시해 새 파일이 늦게 보인다. 있는지는 WebDAV `GET` 으로 확인한다.
- 폴더 권한(ACL)은 WebDAV 로 바꿀 수 없다 — DSM 에서.

## PR #14 — 데모 사이트 싱크

**증상.** 데모(`omnis-omega`)가 9월 2일 배포에 멈춰 있었다.

**원인.** Vercel 데모 프로젝트 `omnis` 의 GitHub 연결이 없었다(`link: null`). 운영 `omnis-hadd` 만 main 에 연결돼 있었다.

**해결 순서가 중요했던 이유.** 연결하는 순간 main 이 배포된다. 그 전에
1. 코드: NAS 가 없는 데모에서 업로드 · 다운로드 UI 를 숨기고 API 403(`lib/demo.ts`)
2. 데모 DB: 밀린 마이그레이션 20개 적용 → 시드
3. 그 다음 연결, 빌드 명령 `prisma migrate deploy && npm run build`(데모 DB 에만 — 더미라 안전)

**함정들.**
- **데모 시드의 `deleteMany` 는 순서가 끝이 없다.** 방문자가 만든 질의 · 북마크 · 활동 기록이 FK 로 사용자를 잡고 있다 → 마이그레이션 기록만 남기고 전 테이블 `TRUNCATE … CASCADE`. 대신 **로컬이 아니면 `DEMO_SEED_ALLOW=1`**, 서명 · 직인 행이 있으면(운영에만 있음) 멈춘다.
- **`lib/demo.ts` 가 `next/server` 를 import 하면 클라이언트 번들이 깨진다** — 클라이언트 컴포넌트도 가져가는 파일이라 `Response.json` 을 쓴다.
- **Turbopack 은 심볼릭 링크 `node_modules` 를 거부한다**("points out of the filesystem root"). worktree 에서는 `npm ci` 로 진짜 설치.
- **`prisma generate` 가 `DATABASE_URL` 을 요구한다**(prisma.config). `.env` 가 없는 worktree 의 postinstall 이 실패한다 → 로컬 주소를 넣고 따로 generate.
- **Vercel API 토큰이 `invalidToken` 으로 거부**돼도 CLI 는 동작한다 — `vercel env pull` 로 받고 쓴 파일은 바로 지운다.

## PR #15 — 채팅 가독성

**1. 묶음 안 줄의 본문이 5px 어긋났다.** 여백 칸은 `w-7`(rem), 아바타는 `28px`. html 배율 아래서 rem 과 px 가 달라진다.
→ 나란히 맞춰야 하는 칸은 단위를 같게(`w-[28px]`).

**2. 아바타 색이 팀장 · 부팀장 · 사원1 모두 같았다.** `h*31+c` 해시를 8로 나눈 나머지가 한글 코드포인트에서 몰렸다.
→ FNV-1a.

**3. 그걸 고치다 색이 `undefined` 가 됐다.** `(h ^ (h >>> 16)) % 8` — `^` 결과는 **부호 있는 32비트**라 음수가 되고, 음수 나머지로 배열을 읽으면 `undefined`.
→ `>>> 0` 으로 부호를 없앤 뒤 나눈다. 임의 이름 5,000개로 `undefined` 0 확인.

**다음에.** 해시로 색 · 버킷을 고르면 실제 이름 목록으로 분포를 찍어 본다. 비트 연산 뒤 인덱스로 쓰기 전에 `>>> 0`.

## PR #16 — AI 대기 UX

**1. 스레드 답장이 AI 재구성을 기다려 입력창이 막혔다.** 이전 실측 8~13초, 이번 점검에서는 Gemini 호출만 **약 45초**(7,006 토큰).

**3. 채팅 패널 🤖 줄이 380px 패널 밖으로 잘렸다.** `whitespace-nowrap` 에 재구성 요약이 길어졌다 → 줄바꿈.

**4. `/업무` 창을 다시 열면 누른 담당자가 되돌려졌다.** 직전 목록 · 값이 잠깐 남아, 그 사이 누른 칩이 곧이어 들어온 @멘션 초기값에 덮였다(시나리오 녹화에서 김아리 → 노혜린 칩 `aria-pressed=false` 로 재현). 사람도 로딩 중에 누르면 같다.
→ 이번 명령의 초기값이 들어오기 전에는 칩 대신 자리 표시만, AI 자동완성도 잠근다.

**5. 시나리오 도우미가 「갱신 중」 줄이 뜨기 전에 "없음" 을 확인했다.** 그래서 AI 가 끝나기 전에 다음 글을 보냈다.

## PR #17 — 요청 한도

**증상.** 버셀 메일 — 무료 팀 Edge Requests 100만 건 75%(9/14 15:13) → 100%(9/15 11:21). 넘으면 프로젝트가 자동 일시 중지되고, 운영 · 데모 · 허브 · 홈페이지가 한 한도를 같이 쓴다.

**측정.** 운영 요청 로그 5,000건(11:33~11:37): **시간당 약 6.8만 건.** 20분 동안 5.3만~6.7만 건 유지. 데모 · 홈페이지 · 허브는 1시간 0~2건.

| 비중 | 요청 |
|---|---|
| 65.6% | `GET /omnis/api/ip-mcp` |
| 33.0% | `GET /omnis/api/notifications` |
| 1.3% | `GET /omnis/api/chat/messages` |

**원인 1 — MCP 스트림 GET 재연결.** ip-mcp 는 모든 GET 에 `200` + 서버 정보 JSON 을 주고 끊었다. Streamable HTTP 클라이언트는 서버가 먼저 보낼 메시지를 받으려 `GET`(`Accept: text/event-stream`)을 여는데, 규약상 서버는 SSE 를 열거나 **405** 여야 한다. 끊긴 스트림을 곧바로 다시 여는 것으로 보인다(초당 약 12건). 로그에 클라이언트 정보가 없어 반복 자체는 직접 보지 못했다.
→ 스트림 GET 에 `405 Allow: POST, OPTIONS`. well-known · authorize · download · 일반 GET 은 그대로.

**원인 2 — 안 보이는 탭의 폴링.** 알림 벨이 모든 페이지에서 2.5초마다(탭당 시간당 1,440건), 탭을 숨겨도 돌았다.
→ `hooks/use-visible-interval`: 보이는 탭에서만, 돌아오면 바로 한 번. 알림 15초 + 벨을 열 때 바로 읽기. 채팅 3초 폴링도 보이는 탭에서만. 브라우저 실측: 보이는 16.5초 2건 → 숨김 16.5초 0건 → 복귀 즉시 1건.

**조사 함정.**
- `vercel usage` 는 무료 플랜에서 `Costs not found (404)` — 프로젝트별 사용량은 대시보드에서만.
- `vercel logs --limit` 은 최대 5,000건이고 `--query "path:…"` 필터가 먹지 않아 **최근 몇 분치만** 섞여 온다. 24시간 경로별 비율은 이 방법으로 못 낸다 — 짧은 구간을 여러 번 떠서 속도를 본다.

**다음에.**
- 새 폴링은 처음부터 `useVisibleInterval` 로. 간격은 "사람이 몇 초 늦게 알아도 되는가" 로 정한다.
- MCP · SSE 엔드포인트는 스트림 GET 을 따로 처리한다. 200 으로 답하고 끊으면 재연결 루프가 된다.
- 무료 플랜 한도 메일(75%)이 오면 그날 로그를 5,000건 떠서 경로별로 센다.
