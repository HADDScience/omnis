"최신 대화 맥락으로 업무 확인·추가지시를 했을 때 옴니스 AI 답변·업무 재구성이 맥락을 잇는지 확인"

## 있던 것 → 만든 것

처음 이식(9-02~03)은 서브에이전트에게 파일을 건네고 결과를 받아 오는 수작업 사이클이었다
(`prepare → Claude → apply` 를 11번). 그 프롬프트를 transcript 에서 회수해 `claude -p` 로
자동화하고 한 CLI 로 묶었다.

```
npm run kakao -- ~/Downloads/KakaoTalk_Chat_*.csv [--media DIR] [--dry] [--target prod]
```

| 단계 | 방식 | 근거 |
|---|---|---|
| 분류 | Claude **병렬** (30세션 × 동시 4) | 세션끼리 독립 |
| 구조화 | Claude **순차** (40세션/라운드) | N 라운드가 1..N-1 의 프로젝트·업무를 맥락으로 받아야 한다 |
| 임베딩 | Gemini 100건 묶음 | 건당 호출이면 하루 한도 500 을 이식 한 번에 다 쓴다 |

CSV 파서를 새로 썼으므로 멱등성 키(본문 sha1)가 보존되는지 먼저 쟀다:
옛 CSV 재파싱 9,137건 중 옛 sessions.json 9,136건 **전부 일치** · 세션 id 615개 전부 일치.

## 품질 실측 — 같은 10문항 + 추가지시 3건, 이식 전후

`import-tools/eval.ts` + `$KAKAO_DATA_DIR/eval/scenarios-260907.json`.
문항은 8-21 ~ 9-04 대화에서 실제로 오간 건으로 짰다(애드힐 로고 D 도안화, 케이바이오랩스 검수사진,
발명특허대전 출품, 아떼셀 로고, 비보젤·오가노캐리어 상표, 스티커·스탠드, 박람회 준비물 …).
"근거" 는 답변에 기대 문자열이 있는지만 센 거친 지표다. 판단은 본문을 읽고 했다.

| | 질문 근거 | 비고 |
|---|---|---|
| 이식 전 | 3/27 | 모르는 걸 모른다고 안 하고 옛 자료로 답함 (A9 "최근 기사" = 2025년 기사) |
| 이식 후 | 15/27 | A2·A5·A7 완전 · A10 "찾지 못했습니다" |
| 날짜 청크 후 | **21/27** | A10 브리핑(10시 30분·우창·혜린) 정확 · A4·A8 완전 · A9 만 실패 |

발견한 결함과 처리:

1. **채팅 청크에 날짜가 없었다.** `"정우창의 메시지" + 본문` 만 색인되니 작년 메시지의 "오늘 올렸습니다"
   를 모델이 질문 시점의 오늘로 읽었다(A9 가 "오늘(2026-09-07) 발행" 이라고 답함).
   → `buildChatMessageChunks` 에 `[채팅 2026-08-27 14:27] 이름:` 과 연결된 업무명을 넣었다. 새 메시지에도 같이 적용된다.
2. **추가지시가 "완료" 로 읽힌다.** "최종 확정합니다. 벡터 파일로 정리해 올려주세요" → `complete` →
   완료 확인 대기. 새 지시가 카드에 안 붙는다. 앱의 `rebuildTask` 판정 규칙이고 이식 품질과 별개다. 미처리.
3. **한 세션 = 한 카드** 라 섞인 주제가 한 체크리스트에 들어간다(애드힐 로고 카드에 "AI 특허 기여율 확인").
   처음 설계의 알려진 한계(UC-2). 미처리.
4. **"최근" 은 벡터 검색이 모른다.** A9 "최근 올린 기사" 는 8-27 메시지(WISET·화성지산학)가 top-8 에 못 들고
   2025년 기사가 나온다. 시간 조건에 가중치를 주는 검색이 없다. 미처리.
5. **평가가 DB 를 오염시킨다.** 이식 전 실측 때 `#애드힐` 이 옛 카드에 붙어 재구성됐고, 그 결과가 이식 후 A1 답변에 섞였다.
   로컬 스냅샷이라 다음 `db:snapshot` 이 지운다. 프로덕션에는 eval 을 돌리지 않는다.

추가지시 재구성(B): 3건 중 2건이 `complete` 로 읽혀 완료 확인 대기가 되었고(결함 2), 1건(아떼셀)은 `rebuild` 로
기존 항목 하나를 체크하고 "상표 출원 회신 확인 및 공유" 를 새 항목으로 붙였다 — 이식된 세션 메시지가 카드에
연결돼 있어 재구성이 옛 맥락 위에서 돈다는 확인.

## 프로덕션 반영

로컬과 같은 출발점(9,136 / 421) 확인. 구조화 결과는 `structure/drafts.json` 캐시(594세션)에서 적용하므로

## 톡 클라우드(카톡 유료 백업)로 첨부를 가져올 수 있나

없다 — 톡 클라우드는 웹에서 보는 백업이고 API 가 없다. 그리고 필요도 없다: 카톡 PC 앱의
채팅방 서랍(사진·파일)에서 폴더로 저장할 수 있고, CSV 에 `File: 이름.pdf` 가 남으므로 이름으로 짝이 맞는다.
`Photo` 는 이름이 없어서 파일명에 박힌 시각(`KakaoTalk_Photo_2026-09-03-15-30-14 001.jpeg`)으로 ±3분 안을 찾는다.
`--media DIR` 로 구현했다. 합성 파일로 `--dry` 매칭만 확인했다(이름 2 · 시각 2 · 무관 파일 남김). NAS 업로드 경로와
사진 파일명의 시각이 전송 시각인지 저장 시각인지는 **실물 폴더로 확인해야 한다**. 현재 CSV 의 자리표시는 파일 658 · 사진 1,542 건.
