# 2026-09-16 — 고친 글의 `#업무` 로 연결을 다시 잡는다 (검증)

## 왜

전체 채팅에 업무 얘기를 그냥 쓴 뒤, 고쳐서 `#슬러그` 를 넣어도 **아무 일도 일어나지 않았다.**
보낼 때는 `#슬러그` 로 `taskId` 를 붙이는데(`lib/chat-post.ts`), 고칠 때는 본문만 바꿨기 때문이다.
화면에는 칩이 보여 연결된 것처럼 착각하기 쉬운데, 스레드는 `taskId` 로 읽으므로 그 글은 오지 않는다.

## 무엇

| 규칙 | 어떻게 |
|---|---|
| 뒤늦게 붙이기 | 고친 본문의 첫 `#슬러그` 로 `taskId` 를 잡는다. 안 붙어 있던 글이 그 업무 스레드에 나타나고 재구성이 돈다 |
| **옮기기** (작업지시자 결정) | 이미 다른 업무에 붙은 글도 옮긴다. **두 업무를 모두 다시 구성한다** — 떠난 쪽은 그 글이 빠진 채로, 온 쪽은 붙은 채로 카드가 맞아야 한다 |
| 멘션 | `replaceMentions` 로 **갈아끼운다**. 보낼 때 쓰는 `persistMentions` 는 더하기만 해서, 고칠 때 쓰면 옛 멘션이 남아 라우팅이 옛 업무를 가리킨다 |
| 없는 슬러그 | 연결을 바꾸지 않는다 — 오타로 글이 업무에서 떨어지지 않게 |

응답에 `_taskId` · `_movedFrom` 을 실어 화면이 어디로 갔는지 안다.

## 실측 — 로컬 dev(3006) · DB `omnis_chat_check`

```
1) 태그 없이 전체 채팅에 쓰기      taskId=None · _rebuild=None
2) 고쳐서 #뉴로힐-검사-키트… 붙임   taskId=3938109f… · _rebuild=queued · movedFrom=None
   DB 연결 → 09150213-뉴로힐-검사-키트-구성품사양서-정리
3) #자가검사-앱-프로토타입… 로 옮김  taskId=bb29f12e… · movedFrom=3938109f…
   재구성 기록 3건(rebuild · complete · info) — 양쪽 업무가 각각 돌았다
4) 다시 첫 업무로 옮김              멘션 1건만 남음 (갈아끼우기 확인)
```

고치기 전에는 3)에서 멘션이 2건 쌓였다 — `replaceMentions` 를 넣어 고쳤다.

```
$ npm run verify
✖ 42 problems (0 errors, 42 warnings)   # 경고는 전부 기존 dashboard · tasks · crm 파일
```

## 알려진 것

- 완료된 업무로 옮기면 그 업무의 재구성이 돈다. 보낼 때의 `referenceOnly` 규칙(완료 업무 `#멘션` 은 참조)
  과는 다른데, 고치기는 「이 글을 이 업무에 넣겠다」 는 뜻이 분명해 그대로 둔다.
- 화면에는 아직 「옮겼습니다」 안내가 없다. 응답에 `_movedFrom` 은 실려 있다.
