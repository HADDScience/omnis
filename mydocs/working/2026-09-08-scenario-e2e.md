# 2026-09-08 — 도입 시나리오 E2E (4명 동시, 목킹 없음)

작업지시: 실제 도입 흐름 — 대표 전체 지시 → 팀장 분배 → 실무 2명 완료보고 → 팀장 취합 보고 —
를 Playwright 로 "사용자의 실제 행동" 그대로, 4명을 동시에 띄워서 돌릴 수 있게.

## 되나

된다. Playwright 는 `browser.newContext()` 마다 세션 쿠키가 따로라, 테스트 하나 안에서
컨텍스트 4개를 만들면 4명이 동시에 로그인해 있다. 각 화면이 3초 채팅 폴링·2.5초 알림 폴링을
스스로 돌리므로, 한 사람이 쓴 것이 다른 사람 화면에 "도착"하는 것까지 실제 경로로 본다.
서버·DB·Gemini 전부 실물이다. 목킹은 없다.

```
npm run test:scenario            # 헤드리스, 컨텍스트 4개 영상·트레이스 전부 저장
npm run test:scenario:headed     # 창 4개가 실제로 뜬다
BASE_URL=http://localhost:3001 … # 다른 포트의 서버를 가리킬 때
```

계정 비밀번호는 `tests/scenario/accounts.local.json` (`{"이름": "비밀번호"}`, gitignore) 또는
`E2E_ACCOUNTS` 환경변수. 저장소는 public 이라 파일에 넣지 않는다.

## 흐름 (tests/scenario/kickoff.spec.ts)

| 단계 | 누가 | 화면에서 하는 일 | 실제 경로 |
|---|---|---|---|
| 1 | 대표 허채정 | 전체 채팅에 방향 공지 → `/업무 @김아리 …` → 「업무 등록」 모달 → AI 자동완성 → 등록 | `/api/ai/structure-task` · `/api/tasks` · 채팅 카드 게시 · 담당자 알림 |
| 2 | 팀장 김아리 | 공지가 폴링으로 도착 → 벨 「수락」 → 분배 공지 → `/업무 @정우창`, `/업무 @노혜린` 등록 | 위와 같음 ×2 |
| 3 | 정우창 · 노혜린 **동시** | 「수락」 → 업무 상세 「이 업무」 스레드에 진행 보고 → 완료 보고 → 「완료로 표시」 | `postChatMessage` → `rebuildTask`(Gemini) → `complete` 면 담당자에게 완료 확인 알림 → `PATCH /api/notifications` → DONE + 지시자 알림 |
| 4 | 팀장 | 「업무 완료」 알림 2건 확인 → 두 업무 상태 「완료」 확인 → 대표 업무 스레드에 취합 보고 → 「완료로 표시」 | 3 과 같음 |
| 5 | 대표 | 「업무 완료」 알림 → 업무 「완료」, 스레드에 취합 보고 | 화면 + `/api/tasks` 로 3건 DONE 재확인 |

매 실행마다 제목에 `[MMDDHHmm]` 태그를 붙여 이전 실행의 업무·알림과 섞이지 않는다.

## AI 판정이 흔들릴 때

완료 보고를 Gemini 가 `complete` 로 읽어야 「완료 확인」 알림이 온다. 진행 보고(`rebuild`)로 읽으면
알림이 없다. 그때는 사람이 하듯 업무 상세의 「업무 완료」 버튼을 누르고, 리포트 annotation
`완료 경로 · 이름` 에 `ai-confirm` / `manual-button` 으로 남긴다. 세 건 모두 `ai-confirm` 이면
AI 가 완료를 제대로 읽은 것이고, `manual-button` 이 있으면 그 문장이 판정 규칙을 못 탄 것이다.

## 셀렉터 근거

- 담당자 칩 접근성 이름은 아바타 이니셜이 붙어 `"김 김아리"` — 이름 끝으로 맞춘다.
- 「전체」 버튼은 패널 탭·최근 스레드 필터·대시보드 필터에 있다 — `aside` 안 첫 번째(탭)를 쓴다.
- 새 알림 토스트가 우상단 벨을 몇 초 덮는다 — 벨은 포커스 + Enter 로 연다.
- 알림 벨 버튼에 `aria-label="알림"` 을 이번에 붙였다(전에는 아이콘만, 규칙 26).
- 스레드 답장은 서버가 Gemini 재구성을 끝낸 뒤 응답하므로, 입력창이 비워지는 순간 = AI 처리 끝.

`새 업무 → 수락 → 업무 확인 → (재구성) → 완료 확인 → 완료로 표시 → 지시자에게 업무 완료` 가 3건 모두 끊김 없이 이어졌다.
AI 구조화 2~4초, 스레드 답장의 재구성 8~13초.

통과까지 11번 돌렸다. 앞의 10번은 시나리오가 아니라 환경·셀렉터 문제였다:

| 회 | 막힌 곳 | 원인 → 처리 |
|---|---|---|
| 1 | 로그인 1명 실패 | 로컬 DB 의 정우창 비밀번호가 시드값과 달랐다 → 로컬 DB 에서 시드값으로 되돌림 (프로덕션 무관) |
| 2 | 15분 멈춤 | 디스크 0 바이트 — 영상 4개(4.1GB) + 트레이스 스크린샷(35k장 2.1GB). 이 머신은 평소 free 1~8GB 를 오간다(colima 데이터디스크 11GB 등) → 녹화·트레이스 기본 끔, `actionTimeout` 15초 |
| 3~4 | 「전체」 클릭 | 대시보드 필터·최근 스레드 필터에 같은 이름 버튼 → `aside` 안으로 한정 |
| 5 | 알림 벨 클릭 | 열린 패널이 헤더 오른쪽을 덮는다 → 벨 전에 패널 닫기 |
| 6 | 「수락」 뒤 검증 | AI 자동완성이 제목의 실행 태그를 지워 이전 실행의 같은 이름 알림이 먼저 잡힘 → 등록 전에 태그를 제목에 되돌림 |
| 7 | 「업무 완료」 버튼 | 누른 직후 페이지 이동으로 요청이 끊김(서버 `aborted`) → 응답까지 대기 |
| 8~9 | 「완료로 표시」 못 찾음 | **새 알림 토스트가 벨을 몇 초 덮는다** → 벨은 포커스 + Enter 로 연다. 업무명은 AI 재구성이 바꾸므로 알림은 `#슬러그` 로 찾는다 |

## 시나리오가 드러낸 제품 쪽 사실

1. **🤖 시스템 메시지의 작성자가 대표다.** `lib/chat-post.ts` 는 `HADD MCP` 사용자가 없으면 첫 ADMIN 을 쓴다.
   시드에 `HADD MCP` 가 없으니 재구성·완료 대기 메시지가 스레드에 「허채정」 이름으로 찍힌다. 프로덕션 DB 도 읽어 봤다 — `HADD MCP` 없음, 첫 ADMIN 허채정. 같은 일이 일어난다.
2. **상세 화면의 「업무 완료」 버튼으로 끝내면 지시자에게 알림이 없다.** 알림의 「완료로 표시」 경로만 `notifyInstructor` 를 부른다 (7회차에서 확인).
3. **진행 보고에도 AI 가 업무명을 바꾼다.** 노혜린 업무가 첫 보고 뒤 `업무명 변경` 됐다. 슬러그는 그대로라 멘션은 살지만, 알림 제목과 카드 제목이 달라진다.
4. 토스트가 헤더의 벨을 덮는 것은 사람에게도 같다 — 알림이 잦은 순간에 벨을 누르면 토스트가 눌린다.

로컬 DB 에는 실패한 실행의 업무(태그 `[090805xx]`)와 미응답 알림이 남아 있다. 스냅샷이라 다음 `db:snapshot` 이 지운다.
