# 2026-09-07 — 한 도메인 이전 1~2단계 결과

계획서: [`plans/2026-09-07-one-domain.md`](../plans/2026-09-07-one-domain.md). 작업지시자 승인: 1~2단계.

## 1단계 — 옴니스 basePath 대비 (`701c6a5`, 켜지 않음)

| 무엇 | 처리 |
|---|---|
| `fetch("/api/…")` 80곳 + 간접 4곳 | `lib/base-path.apiUrl()` — Next 는 fetch·`<a href>`·`<img src>` 에 basePath 를 안 붙인다 |
| `File.path` 를 그리는 4곳 · NAS 링크 2곳 | 그릴 때 `apiUrl()` — DB 값은 그대로 |
| NextAuth | 라우트 핸들러가 basePath 뗀 경로를 받는데 NextAuth 는 자기 basePath 로 동작을 읽고 콜백도 만든다 → 핸들러에서 경로를 도로 붙여 넘김. `redirect` 콜백이 앱 안 경로에 basePath 를 붙임. `next-auth/react` 는 클라이언트에서 `NEXTAUTH_URL` 경로를 basePath 로 삼아 next.config `env` 로 실어 줌 |
| MCP issuer · 승인 redirect · SSO 로그인 되돌림 | 프록시 뒤에선 요청 origin 이 내부 호스트 → `PUBLIC_URL` 우선 (`publicBase`/`publicUrl`) |
| `next/navigation` `redirect("/login")` | 실측상 basePath 가 자동으로 붙는다 (`/omnis/login`). 손대지 않음 |

로컬 실측 — `NEXT_PUBLIC_BASE_PATH=/omnis NEXTAUTH_URL=http://localhost:3000/omnis/api/auth`:

```
/                     404                       (루트는 홈페이지 몫)
/omnis/login          200  자산 /omnis/_next/…
/omnis/dashboard      307 → /omnis/login
credentials 로그인    302 → /omnis/dashboard · 세션·/api/tasks·/crm/inventory 200
signout               302 → /omnis/
providers.callbackUrl …/omnis/api/auth/callback/credentials
MCP issuer            http://localhost:3000/omnis/api/ip-mcp
```

끈 상태 회귀: verify-ip-mcp 37/37 · verify-omnis-mcp 25/25 · 프로덕션 HTTP(로그인·SSO 되돌림·issuer) 변화 없음.
verify-sso 의 서명 검증은 로컬에 `SSO_SIGNING_KEY` 가 없어 못 돌렸다 — `lib/sso.ts` 는 건드리지 않았고, SSO 되돌림 주소는 프로덕션 HTTP 로 확인했다.

## 2단계 — haddscience 프로젝트 (hadd-website `b63d56d`)

`vercel.json`(rewrites) + `scripts/build-hub.sh`(허브를 받아 out/hub 로). 프로젝트 `haddscience`, env `DEPLOY_TARGET=pages`(색인 차단 — DNS 붙일 때 뺀다).

```
haddscience.vercel.app
  /  /ko  /en  /admin        200
  /hub  /hub/account/        200  자산 /hub/_next/…
  /omnis/login               omnis-hadd 로 프록시됨 — basePath 가 아직 꺼져 있어 3단계 전엔 정상 응답 아님
  /.well-known/…/omnis/api/ip-mcp  같은 이유로 404 (3단계 뒤 200 이어야 한다)
  robots.txt                 Disallow: /  (DEPLOY_TARGET=pages)
```

`trailingSlash: true` 를 vercel.json 에 넣었더니 `/omnis/api/…` 까지 308 로 슬래시가 붙어 뺐다. 정적 파일은 없어도 `/ko`·`/ko/` 둘 다 200.

## 사고 — 다른 세션의 브랜치 위에 배포했다

1단계 커밋 시점에 이 체크아웃(`~/work/omnis-local`)이 다른 세션의 `feat/website-admin-sso` 로 바뀌어 있었다.
제 커밋이 그 위에 얹혔고 `vercel deploy --prod` 가 그 브랜치를 올렸다 — 미머지 3커밋(웹사이트 GitHub 프록시·SSO 앱 등록)이
승인 없이 프로덕션에 들어갔다. 겹치는 파일은 없었다. 바로잡음: 커밋을 main 으로 cherry-pick(`701c6a5`), 브랜치는 원래 끝
`50eba82` 로 reset, main 에서 재배포. **앞으로 이 작업은 `~/work/omnis-main`(main 워크트리)에서만 한다** — 체크아웃을 공유하는
세션과 브랜치가 섞이지 않게.

## 3~4단계 — 켜기 · 주변 앱 (같은 날 저녁)

작업지시자가 구글·카카오 콜백을 등록한 뒤:

`SSO_ISSUER=https://omnis-hadd.vercel.app`(SSO 토큰 issuer 는 그대로 — 소비자가 검증하는 값이라 주소와 분리). `bdc10e7` 배포.
