### 입력 · 출력

| 입력 | 뜻 |
|---|---|
| `from` | 시작 날짜(서울). 기본 오늘 |
| `to` | 끝 날짜(서울, 그날 포함). 기본 from 부터 7일 |
| `calendar` | 캘린더 이름 일부. 볼 수 있는 캘린더 안에서만 찾는다 |
| `query` | 제목 · 장소에서 찾을 말. 띄어 쓴 말은 모두 든 것만(「혜린 외근」) |
| `all_day` | true 종일만 · false 시간 있는 것만 |

- **기간 상한 62일.** 넘으면 오류로 돌려보내지 않고 `from + 61일` 까지 읽은 뒤 「요청한 끝 X 은 … 까지만 읽었다. 그 뒤는 from 을 옮겨 다시 부른다」 를 적는다. 거꾸로 된 기간 · 없는 날짜는 오류
- **건수 상한 100.** 넘으면 앞 100건과 「N건 중 앞 100건만 보였다(잘림). … 좁혀 다시 부른다」
- 한 줄: `- 2026-11-05(목) 13:00–17:00 · 제목 · [캘린더] · 장소 … · 반복 · 미정`. 종일은 `종일`, 여러 날 종일은 `A ~ B 종일`, 날을 넘는 시간 일정은 `A 16:00 – B 17:00`. 미정은 STATUS:TENTATIVE(화면이 흐리게 그리는 것)
- 머리: 기간 · 건수 · 거른 조건 · 「오늘: 2026-10-30(금) (Asia/Seoul)」 · **마지막 동기화** — 캘린더마다 시각, 가장 오래된 것 기준 「웍스 원본과 최대 약 N시간 차이」. 동기화된 적 없는 캘린더가 있으면 그렇다고 적는다

### 권한 · 화면과 같게 한 것

- **보이는 캘린더**: 탭과 같은 `getCalendarItems` → `worksPart` → `visibleCalendarFilter`. 관리자는 `CALDAV_CALENDARS` 의 캘린더 전부, 구성원은 관리자가 연(audience ALL) 캘린더만. 권한은 **요청한 사람의 Caller** 그대로(에이전트 `callerFor` · MCP 토큰 · 질문 경로 모두 `runTool` 한 길)
- 못 보는 캘린더는 **이름도** 나오지 않는다. 그 이름으로 `calendar` 를 집어 불러도 「맞는 캘린더가 없습니다 · 볼 수 있는 캘린더: …」(볼 수 있는 것만)
- **설명(description)은 싣지 않는다** — 캘린더 탭의 일정 줄(`day-agenda.tsx`)이 시각 · 캘린더 · 제목 · 장소 · 반복만 그린다. 참석자 · 주최자도 화면에 없어 싣지 않는다
- **비공개 일정**: 동기화(`lib/caldav/sync.ts`)가 `CLASS` 를 저장하지 않아 화면도 가리지 않는다. 도구도 같다. 웍스에서 비공개로 둔 일정을 옴니스에서 가리려면 `ExternalCalendarEvent` 에 칸을 더해야 한다(마이그레이션) — 이번에는 하지 않았다
- 반복 · EXDATE · 예외 회차 · CANCELLED: `worksItems` 그대로(회차마다 한 줄)
- **사람**: 웍스 일정은 회사 캘린더라 사람별 칸이 없다. 「누가 외근」 은 제목에 적힌 이름(`[혜린] …`)으로 찾는다(`query`). 따로 `person` 인자는 두지 않았다 — 주최자 · 참석자 메일로 맞추면 화면에 없는 정보를 도구로 드러내게 된다. 프롬프트가 이 사실을 답에 밝히게 한다

### 동기화를 부르지 않는 이유

캘린더 탭은 열 때 `POST /api/calendar/sync`(60초에 한 번)로 웍스를 당긴다. 도구는 이것을 부르지 않는다 — 읽기 도구가 외부 요청 · DB 쓰기 · 새 일정 알림(`calendar-notify`)을 일으키지 않게. 그 대신 마지막 동기화 시각과 「최대 N시간」 을 돌려주고 모델이 답 끝에 한 줄로 붙인다. 동기화는 탭을 누군가 열 때와 하루 한 번 크론이므로 **최대 약 하루** 늦을 수 있다. 도구가 부르기 전에 동기화하게 바꾸려면 `syncWorksCalendars()` 한 줄이면 되지만 응답이 웍스 왕복만큼 늦어진다 — 작업지시자 판단.

### 어디에 열었나 — 근거

| 경로 | 열었나 | 근거 |
|---|---|---|
| 에이전트(옴니스 1:1 방) `AGENT_READ_TOOLS` | 연다 · 자동 | 읽기. 요청 본론 |
| MCP(hadd-omnis) `OMNIS_TOOLS` | 연다 | 같은 `runTool`. 이 목록의 읽기 도구(list_tasks · list_company_records · list_tax_invoices …)는 모두 MCP 에 열려 있다. 권한은 토큰의 사람 그대로라 MCP 에서도 탭보다 넓지 않다 |
| 질문 경로(Gemini `/omnis/ask` · `ask_omnis`) `ROUTE_READ_TOOLS` | 연다 | 이 목록은 「MCP 읽기 도구 전부」 다(`omnis-ask-tools.test.ts` 셋째 시험이 MCP 도구를 읽기 · 쓰기 어느 쪽에 둘지 정하게 한다). 쓰기가 아니라 확인 단계가 필요 없다 |

질문 경로가 모델에게 주던 오늘은 `new Date().toISOString().slice(0, 10)`(UTC 날짜)라 서울 0~9시에 하루 어긋났다. 일정 질문을 열면서 서울 날짜 · 요일로 바꿨다.

### 무엇을 바꿨나

- `lib/agent/prompt.ts` — `CALENDAR_WRITE_RULE` · `WORKS_CALENDAR_URL`(https://calendar.worksmobile.com). 에이전트 지시문의 「쓰기」 절 뒤에 넣었다
  - 쓸 수 없다고 짧게 + 「웍스 캘린더에 직접 등록해 주세요」 + 링크
  - 「등록했습니다」「옮겼습니다」「지웠습니다」 금지
  - create_task · draft_document 같은 다른 쓰기 도구로 일정을 대신 만들지 않는다. 사용자가 「업무로 만들어 줘」 라고 분명히 했을 때만 업무 제안
  - 등록할 내용을 칸 다섯으로: 제목 · 날짜/시간(`YYYY-MM-DD(요일) HH:MM–HH:MM (Asia/Seoul)`, 「다음 주 화요일」 은 오늘(서울) 기준으로 풂) · 장소 · 참석자 · 메모. 말하지 않은 칸은 「?」, 끝 시각을 모르면 「?」
  - 수정 · 삭제는 list_calendar 로 그 일정을 찾아 지금 값과 바꿀 것을 적는다. 날짜를 알면 그날을 읽어 겹치는 일정이 있으면 한 줄
- `lib/omnis-ask.ts` — 질문 경로(Gemini) 시스템 프롬프트에 **같은 문장**을 넣었다. 그 경로는 쓰기 도구가 없지만 사용자는 같은 부탁을 할 수 있다. `routeSystemPrompt` 를 시험하려고 export 했다
- **카드 · 복사 단추는 만들지 않았다.** 기존 [복사] 단추는 확인 카드(`agent-card.tsx`, 쓰기 · 결과물 도구가 만드는 것)에만 있다. 이번에는 쓰는 것이 없어 카드를 만들 이유가 없고, 「쓰기 도구를 만들지 말 것」 이 요청이었다. 대신 칸 이름이 고정된 목록이라 길게 눌러 그대로 옮겨 적을 수 있다
