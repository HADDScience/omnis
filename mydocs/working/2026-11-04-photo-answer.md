### narrow-audit

전체 경로에서 잘린 화면 집합이 두 트리에서 같다(폭 · 경로 기준 차이 0). 넘침 0 · 뚫고 나감 0, 작은 터치 타깃 합계 575 로 같다.
사진 묶음 방의 잘림은 방 제목 · 부제 · 참고자료 제목의 `truncate` 이고 작은 타깃은 본문 각주 단추다.
main 에서는 묶음이 그려지지 않으므로 묶음 자체가 더한 잘림이나 작은 타깃은 없다.
이 게이트는 main 에서 이미 실패하므로 이 PR 범위 밖으로 둔다. 면제가 아니라 남은 일이다.

### 온보딩 · 캔버스 더블클릭

이전 실행에서 실패한 두 시험은 위 실행에서 브랜치 · main 모두 통과했다.

`scripts/e2e-local.mjs`(dev 서버)로도 한 번씩 돌렸을 때는 브랜치 18건, main 4건이 실패했고, 온보딩 장면 순서는 둘 다 실패했다.
실패는 페이지 이동 시간 초과 · `ERR_EMPTY_RESPONSE` · `ERR_CONNECTION_REFUSED` 가 대부분이고 dev 응답이 최대 49초까지 늘어졌다.
이 두 번은 main 의 다른 커밋 위였고, 브랜치 실행에는 다른 검사가 겹쳐 있었다. 빌드 서버 실행에서는 재현되지 않아 dev 서버의 부하 영향으로 본다.
dev 방식으로 조건을 맞춰 다시 재지는 않았다.

## 확인하지 못한 것

- 이번 비교는 데모 시드 DB 다. 데이터가 긴 운영 스냅샷의 잘림은 다를 수 있다.
- 묶음 시험의 사진은 `/raw` 를 가로챈 1×1 PNG 다. 실제 사진 표시는 rebase 전 코드에서만 확인했다.
- 실제 모델 호출은 없다. rebase 뒤 프롬프트로 사진에 번호를 빠짐없이 다는지는 재지 않았다.
- 프리뷰 · 운영 배포본, 실기기 터치와 밀어 넘기기.
- 운영 검색의 재측정. 이전 측정 때 설명이 끝나지 않은 사진이 많아 정답이 있는 표본 8개 중 설명 완료는 1개였고, 그 1개만 PHOTO 1위로 나왔다.
