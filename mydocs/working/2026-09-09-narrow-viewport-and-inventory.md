## 왜 — 시스템 설정이 웹에 닿는 경로

"글꼴 크기를 키운다"가 웹에 그대로 오지 않는다. 경로가 넷인데 셋은 같은 곳으로 모인다.

| 경로 | 웹에 도달하는 형태 |
|---|---|
| 안드로이드 시스템 글꼴 크기 | **Chrome 웹 콘텐츠에는 적용되지 않는다.** Chrome 은 자체 설정을 쓴다 |
| Chrome 설정 → 접근성 → 기본 확대/축소 (50~200%) | 페이지 줌 = **CSS 뷰포트가 좁아진다** |
| 안드로이드 시스템 화면 크기(디스플레이 크기) | 밀도 변경 = **CSS 뷰포트가 좁아진다** |
| 인앱 웹뷰(카톡 등) | `WebSettings.textZoom` — 여기만 **글자만 커지고 박스는 그대로** |

앞의 셋이 "뷰포트가 좁아진다"로 수렴하므로, 대응은 **320px 아래까지 견디는 유동
레이아웃**이다. 320 → 200px 로 내려 재는 실측 스크립트를 만든 이유가 이것이다.

토스가 SLASH 23 「누구나 쓸 수 있는 접근성 높은 토스 만들기」(최동근)에서 공유한
규칙을 기준으로 삼았다 — **사용자 환경에 따라 주어지는 정보량이 달라지면 안 된다.**
말줄임으로 도망가지 않고, 좌우 배치를 위아래로 바꾸고, 공간이 없으면 다른 자리에서
전부 보여 준다. 토스는 큰 글씨 전용 화면을 따로 만들지 않고 디자인 시스템의 컴포넌트
스펙에 접근성 칸을 고정으로 두어 누적시켰다.

- <https://toss.im/slash-23/session-detail/B2-1>
- <https://ditoday.com/누구나-편리한-토스-uiux-개발-이야기/>

## 실측

측정 스크립트는 세션 임시 폴더에 있었다. 저장소에 넣지 않았다 — 넣을지는 아래
"남은 것" 참고.

측정 대상: 18개 화면 × 320 · 280 · 240 · 200px, 로그인 상태, 로컬 스냅샷(업무 610건).
잰 것 넷 — 가로 오버플로 / `overflow:hidden` 에 잘린 양 / 말줄임으로 사라진 양 /
44px 미만 터치 타깃.

### 가로 오버플로 — 전 구간 0 (전·후 모두)

`7b9beff`(폴더블·태블릿 뷰포트 작업)이 200px 까지 버티고 있었다. 이번에 깨진 것은
오버플로가 아니라 **잘림**이었다.

### 잘림 — 320px

```
전:  잘린 화면 8 / 18       최대 잘림 252px
후:  잘린 화면 2 / 18       최대 잘림 114px
```

잘린 양이 컸던 자리:

| 화면 | 전 | 무엇 |
|---|---|---|
| 대시보드 · 채팅 | 252px | 업무 제목 `truncate text-[13px]` |
| 옴니스 | 240px | 카드 제목 / 설명 180px |
| 업무 상세 | 234px | 헤더 제목 |
| 재고 | 141px | 이동 메모 |
| 업무 목록 | 110px | 프로젝트 배지 `max-w-[160px]` — 폭과 무관하게 12건 전부 |
| 팀원별 현황 | 145px | 카드가 통째로 (원인은 `min-w-0` 누락) |

남은 2건은 **업무 상세 헤더 제목(114px)** 과 **칸반 슬러그(50px)** 다. 둘 다 같은
정보가 본문에 온전히 있어 그대로 뒀다 — 헤더 제목은 본문 맨 위에 다시 나오고,
슬러그는 제목에서 파생된 값이다.

### 터치 타깃

```
전:  헤더 버튼 26×26      18개 화면 전부
후:  헤더 버튼 44×44      헤더 높이 39px → 52px (터치 기기만)
```

`.touch-target` 클래스는 `globals.css` 에 정의만 있고 **쓰는 곳이 한 군데도 없었다**.
정의를 44×44 로 하고 실제로 붙였다 — 사이드바 토글 · 채팅 열기 · 알림 · 패널 닫기 ·
패널 탭.

44px 이 `h-12` 헤더에 들어가지 않는다. `h-12` 는 3rem 인데 루트 글꼴이 81.25% 라
39px 이다. 그래서 터치 기기에서만 헤더를 52px 로 키웠다.

### 루트 글꼴 — 사용자 설정을 따라가게

```
전:  html { font-size: 13px }
     브라우저 기본 글꼴 16px → 13px
     브라우저 기본 글꼴 20px → 13px   ← 사용자 설정이 무시된다

후:  html { font-size: 81.25% }       (= 13/16)
     브라우저 기본 글꼴 16px → 13px   ← 보이는 크기는 그대로
     브라우저 기본 글꼴 20px → 16.25px
```

`text-[13px]` 같은 고정 px 이 458곳 있어 이 변경만으로 전부 따라오지는 않는다.
루트가 사용자 설정을 막고 있던 것을 걷은 것까지가 이번 범위다.

### 탭 · 구분선 (스크린샷 지적으로 발견)

```
탭    전: TabsList 29px / 트리거 29px  →  트리거 bottom 277 > 리스트 bottom 274 (3px 삐져나옴)
      후: 터치  50px / 44px  bottom 305 < 308
          마우스 33px / 27px  bottom 275 < 278

구분선 전: y 0 ~ 13   (헤더 39px 안에서 맨 위)
      후: y 13 ~ 26  (가운데)
```

## 재고 — 제품 › 타입 › 용량

평평한 목록에서 애드젤이 다섯 줄로 흩어져, 애드젤이 통틀어 몇 개인지를 사람이 눈으로
더해야 했다.

```
애드젤 (ADD Gel)   5종                     54개
  [동결건조]  동결건조   PRD008              0개
  [바이알]    5ml      PRD002  1개에 0.05g  0개
  [세트]     Bottle & Syringe SET PRD007   0개
  [시린지]    2ml      PRD009  1개에 0.02g 54개
            5ml (1ml × 5ea) PRD001         0개
라이브젤 (Live Gel) 3종                     50개
            1ml · 2ml · 3ml                (kind 가 비어 소제목 없음)
```

- 타입이 빈 라이브젤·고정제에 "기타" 같은 이름을 지어 붙이지 않는다. 없는 분류를
  만드는 셈이라 소제목 없이 제품 바로 아래 둔다
- 용량 정렬은 `spec` 문자열이 아니라 `volumeMl` 숫자로. "10ml" 이 "1ml" 옆에 붙지 않게
- 1개당 원료 그램은 **표시할 때만** 반올림한다. 계산에 쓰는 `gramsPerUnit` 을 미리
  자르면 소요량이 틀어진다 (`0.022199999999999998g` 로 나오던 것)

## 품목 보관 — PRD001 · PRD010

사용자 요청으로 애드젤 5ml(1ml × 5ea)와 고정제를 목록에서 내렸다. **행을 지우지 않고
`archived=true`** — PRD001 에 견적 5건·출고 6건, PRD010 에 출고 1건이 걸려 있어
지우면 지난 견적서와 출고 이력이 깨진다.

```
로컬 · 운영(Neon) 양쪽   갱신 2건, 남은 활성 제품 8건
이력 확인               견적 항목 13건 · 출고 23건  (양쪽 동일, 그대로)
```

되돌리려면 `archived` 를 `false` 로 되돌리면 된다.

## 프로젝트 정리 이동

`/settings` 는 내 계정을 보는 자리인데 거기에 프로젝트 병합이 있었다. 프로젝트를
합치면 **남의 업무까지 같이 옮겨간다** — 개인 설정이 아니라 업무 공간의 정리 작업이다.
`/tasks/projects` 로 옮기고 들어가는 길을 `/tasks` 툴바에 뒀다.

## 모바일 사이드바

모바일 사이드바는 화면을 덮는 Sheet 다. 항목을 눌러 이동해도 그대로 열려 있어서
도착한 화면을 보려면 한 번 더 닫아야 했다. 데스크톱은 붙박이 레일이라 건드리지 않는다.

```
390px  메뉴 '업무'        → /tasks                   닫힘 ✓
       빠른 필터 '오늘 마감' → /tasks?filter=due-today  닫힘 ✓
       'Omnis AI'                                    닫힘 ✓
1440px 메뉴 '업무'        → /tasks                   레일 expanded 유지 ✓
```

## 품질 게이트 · 배포

```
npm run verify   exit=0   (기존 lint 에러 1건을 고쳐야 넘을 수 있었다 — 아래)
npm run build    성공, /tasks/projects 라우트 확인
배포본 HTTP      /omnis/login 200 · /omnis/tasks/projects 307 → /omnis/login
배포본 CSS       font-size:81.25% · .touch-target{min-width:44px} · @media(pointer:coarse) 모두 포함
```

`components/settings/linked-accounts.tsx` 의 `reload()` 가 선언보다 먼저 불려 lint 가
막고 있었다. 호이스팅 덕에 돌기는 하지만 `npm run verify` 가 실패해 push 게이트를
못 넘어서 순서만 맞췄다.

**배포는 `origin/main` 에서 워크트리를 따로 떠서 했다.** `vercel deploy` 는 로컬
디렉터리를 그대로 올리는데, 그때 작업 트리에 다른 세션의 미커밋 변경(`lib/ai.ts`
프롬프트 추출 · `bench/` · `package.json`)이 있었다. 그대로 배포하면 검증하지 않은
남의 작업이 운영에 올라간다.

로컬 `main` 은 건드리지 않았다 — 푸시되지 않은 커밋 3건이 있어 `origin/main` 에 직접
머지했다. 그 3건은 배포되지 않았다.

## 남은 것

- **측정 스크립트가 저장소에 없다.** 세션 임시 폴더에 있어 사라진다. `scripts/` 로
  옮기면 `node scripts/narrow-audit.mjs` 로 다시 돌릴 수 있다. 로그인 계정을
  환경변수로 받게 바꿔야 한다
- **로그인이 필요한 배포본 화면은 브라우저로 못 봤다.** 운영 계정이 없고 운영
  비밀번호를 건드리지 않았다. HTTP 상태와 배포된 CSS 내용까지만 확인했다
- 200px 잔여 — 헤더 제목·칸반 슬러그. 위 "잘림" 절에 이유
- `mydocs/orders/20260909.md` 는 다른 세션이 쓰고 있어 이 작업을 적지 않았다
