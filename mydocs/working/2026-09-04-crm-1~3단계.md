## 엑셀에서 발견한 것

### HRP 할인 400,000 이 13건 중 7건에서 실제로 빠지지 않았다

```
HADD240924-001  공급가 1,300,000  할인 400,000  소계   900,000  적용됨
HADD250305-005  공급가 1,800,000  할인 400,000  소계 1,800,000  안 빠짐
HADD250320-006 · 009 · 010 · 011 · 012 · 013   전부 같은 모양
```

단가가 650,000 → 450,000 으로 내려간 시점과 겹친다. 할인을 단가에 녹였는데
할인액 칸의 수식(`상태=활성이면 400,000`)은 계속 값을 채운 것으로 보인다.

대시보드의 "총 HRP 할인액 4,400,000" 중 **2,800,000 이 실제로는 깎이지 않았다**.
실합계 42,186,705 자체는 정확하다 — 할인 칸만 장식이다.

**이식에는 실제로 깎인 금액만 넣었다.** 적힌 값을 그대로 옮기면 앱도 같은
유령을 세게 된다. 되돌리려면 해당 7건의 `discountAmount` 를 400,000 으로
고치면 되지만, 그건 돈에 대한 판단이라 작업지시자 몫이다.

## 도중에 고친 것 셋

### 1. "새로 만들기" 줄이 사라졌다

`Command` 의 커스텀 filter 가 `options` 에서 값을 찾는데, 만들기 줄의 값은
`__create__<검색어>` 라 목록에 없어 걸러졌다. 결과가 없을 때 "아래에서 새로
만들 수 있어요" 안내만 뜨고 **정작 만들 방법이 없었다.**

### 2. 날짜가 하루 밀렸다

`HADD251212-012` 가 `2025-12-11` 로 떴다. xlsx 가 `cellDates` 로 주는 Date 가
`2024-09-23T14:59:08Z` 처럼 자정에서 몇십 초 어긋난다. 날짜 칸은 시각이
아니므로 가장 가까운 UTC 자정으로 맞춘다.

### 3. 코드 채번이 동시 생성에서 깨졌다

만들기가 두 번 눌리자 둘 다 `ORG024` 를 노려 한쪽이 500 이 났다.
"최대값 + 1" 은 읽고 쓰는 사이가 열려 있다. unique 제약에 막힌 쪽만 번호를
다시 뽑아 재시도하게 했다.

거부되어야 하는 경우로 확인했다 — 동시 5건:

```
동시 5건 →  성공 5 / 실패 0
부여된 코드: ORG025 ORG026 ORG027 ORG028 ORG029
중복 코드: 없음
```
