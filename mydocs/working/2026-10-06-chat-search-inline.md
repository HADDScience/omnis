## API

| 요청 | 결과 |
|---|---|
| `q=견적` | total 120 (PR #82 의 전 페이지 집계 120 과 같음) |
| `authorId=김아리` | total 4,915 |
| `authorId=김아리&q=견적` | total 62 |
| `q=__` | total 2 · 목록 2 — **고치기 전에는 목록이 20건(더 있음)이었다.** Prisma `contains` 가 `_` 를 와일드카드로 넘겼다(PR #82 부터 있던 버그) |
| `q=100%` | total 1 · 목록 1 |
| `at=2026-05-14T00:00+09:00` | 대상 2026-05-14 11:06(KST), 31건 중 15번째 |
| `at=2030-01-01…` | 마지막 글 주변, 뒤 더 없음 |
| `at=abc` | 400 |

`total` 을 셀 때 `Prisma.sql` 조각을 끼워 넣었더니 `next dev` 에서만 `syntax error at or near "$2"` 가 났다(같은 쿼리가 tsx 스크립트에선 됐다).
null 이면 꺼지는 조건(`${x}::text IS NULL OR …`)을 쓴 고정 SQL 한 벌로 바꿨다.
