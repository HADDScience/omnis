# 2026-09-23 작업

어제([20260922](20260922.md))는 홈페이지 문의를 CRM 으로 잇고 운영까지 올렸다.
남겨 뒀던 「돌려 보지 않았다」 두 개를 오늘 채웠다.

## 완료

| 상태 | 내용 |
|---|---|
| 완료 | **보관기간 파기가 실제로 지운다.** PR #66 머지·배포. 문의 3년은 3년+1일 / 3년−1일(경계)을 심어 확인했고, 방문 통계 400일 파기는 새로 만들어 500·401·399일로 확인했다. 실측은 `mydocs/working/2026-09-22-website-inquiry-to-crm.md` 의 「3차」 |
| 완료 | **문의 파기에서 `reviewNote` 도 비운다.** 담당자가 자유롭게 쓰는 칸이라 방문자 개인정보가 들어갈 수 있는데, 방침은 3년 뒤 파기를 약속한다. 처리 이유는 이어진 견적·샘플요청의 note 에, 처리 시각은 status·reviewedAt 에 남는다 |

## 남은 것

| 상태 | 내용 |
|---|---|
| 대기 | **파기를 언제 돌릴지.** 두 스크립트 다 로컬에서만 태웠다. 운영에는 3년·400일 지난 데이터가 아직 없어 지울 것이 없다 — 문의는 2026-09-22 부터, 방문 통계는 그 며칠 전부터 쌓이기 시작했다. 실제로 지울 것이 생기는 시점은 2028년 말·2027년 말이다. 크론을 붙일지는 그때 정해도 늦지 않다 |
| 대기 | **사이트 `app/api/hit/route.ts` 에 fetch 타임아웃이 없다.** 방문 통계를 Omnis 로 보내는 곳이다. 빌드를 막지는 않지만 Omnis 가 응답하지 않으면 함수가 응답까지 붙들린다. `hadd-website` 저장소의 **다른 세션 파일**이라 양쪽 다 손대지 않았다. 사이트의 `content/server.ts`·문의 라우트는 그 세션이 PR #13 으로 이미 고쳤다 |
