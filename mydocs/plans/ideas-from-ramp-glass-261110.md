# Ramp Glass 에서 가져올 아이디어 (2026-11-10)

Ramp 가 2026-10-13 에 외부 기업에 공개한 AI 업무 공간 Glass 의 공개 자료를 읽고, 옴니스에 맞는 것만 골랐다.
Glass 의 기능을 그대로 옮기려는 문서가 아니다. 설계 원칙 가운데 옴니스의 채팅 · 업무 카드 · 확인 카드 · MCP 위에 얹을 수 있는 것을 고른 목록이다.

Glass 에 대한 사실은 아래 출처에 있는 것만 썼다. 수치는 Ramp 가 직접 집계한 것이라 여기에 옮기지 않았다.

## 1. 스킬 라이브러리

- **무엇** — 잘 된 프롬프트나 작업 절차를 이름을 붙여 저장해 두고, 동료가 그대로 불러 쓴다. Glass 는 이것을 Skills 라고 부르고 회사 안에서 공유한다(출시 글).
- **옴니스에 맞춘 모양** — 옴니스 세션 하나를 「스킬로 저장」 하면 첫 글(프롬프트)과 쓴 도구 목록이 남는다. 다른 사람은 새 대화에서 스킬을 골라 시작한다. 스킬은 프롬프트일 뿐이라 쓰기 도구는 지금처럼 확인 카드를 거친다. 저장 · 고침에는 작성자와 날짜만 남기고, 별도 검토 절차는 두지 않는다.
- **선행 조건** — 세션을 남과 함께 쓰는 구조(3번). 스킬이 부르는 도구가 앱 AI 와 MCP 에서 같아야 한다 — 이미 맞춰 두었다(`mydocs/plans/2026-11-10-app-ai-mcp-parity.md`).
- **상태** — 아이디어.

## 2. 정정한 규칙을 회사 지식으로

- **무엇** — 대화 중에 사람이 고쳐 준 업무 규칙 · 용어를 한 번 저장하면 그 뒤 모든 사람의 답에 반영된다. Glass 는 「한 번 배우면 회사 전체가 안다」 를 핵심 메시지로 내세운다(출시 글). 회사 공통 배경은 관리자가 넣는다(도움말 「Company context」).
- **옴니스에 맞춘 모양** — 옴니스 답을 사람이 바로잡으면 옴니스가 「이 규칙을 회사 지식으로 남길까요?」 확인 카드를 띄운다. 확인하면 지식 카드(전사 공개)로 저장하고, 에이전트의 지시문에 짧은 규칙 목록으로 붙인다. 지식 카드는 원래 전사 공개라 사람 방 내용을 옮길 때는 확인 카드에서 보이는 그대로만 남긴다.
- **선행 조건** — 규칙 목록이 길어질 때 지시문에 넣을 몫을 고르는 방법(최근 · 자주 쓰인 순). 잘못 저장된 규칙을 되돌리는 화면.
- **상태** — 아이디어.

## 3. AI 세션 공유 · 인계

- **무엇** — AI 대화 자체를 동료와 함께 본다. 동료는 같은 맥락에서 이어 간다. Glass 는 세션을 공유하면 동료가 들어와 전체 맥락을 보고, 막힌 일을 넘길 수 있다고 설명한다(출시 글). 채팅 앱에서 @Glass 로 부르는 길도 있다(도움말).
- **옴니스에 맞춘 모양** — 사람 방(단톡방 · 1:1)에서 `@옴니스` 로 부르면 언급 뒤 글로 세션을 연다. 방에는 시작 · 끝 안내 한 줄만 남고 「열기」 로 세션에 간다. 세션은 그 방 참여자 모두가 보고 이어 묻는다 — 권한은 새로 만들지 않고 방 참여자 조건을 그대로 쓴다. 쓰기 확인 카드는 그 실행을 연 사람만 누르고, 비용도 그 사람에게 잡힌다. 설계: [`2026-11-10-omnis-mention-session.md`](2026-11-10-omnis-mention-session.md).
- **선행 조건** — 없음(이 PR). 다음 단계인 방 밖 세션의 수동 공유 · 인계는 세션 원본 방 칸(`ChatRoom.originRoomId`) 대신 공유 대상 표를 두는 식으로 넓힌다.
- **상태** — **진행 중(이 PR)**. 방 밖 세션의 수동 공유 · 인계는 범위 밖.

## 4. 예약 자동화

- **무엇** — 같은 작업을 일정에 맞춰 되풀이하게 맡긴다. Glass 는 이것을 Automations 라고 부른다(도움말). 사용자가 시키지 않으면 메시지를 보내거나 기록을 바꾸지 않는다는 원칙도 함께 둔다(도움말).
- **옴니스에 맞춘 모양** — 「매주 금요일 오후 주간보고 초안」 「매일 아침 마감 임박 업무 요약」 처럼 프롬프트와 일정을 저장하면 정해진 때에 세션을 열고, 끝나면 정한 방에 3번과 같은 안내 한 줄을 남긴다. 읽기 도구만 쓰고, 쓰기는 확인 카드로 남겨 둔 채 사람을 기다린다.
- **선행 조건** — 3번의 「세션 → 방 안내」 길. 예약 실행의 비용을 누구에게 잡을지(만든 사람). 스킬(1번)이 있으면 예약 대상이 스킬이 된다.
- **상태** — 아이디어.

## 5. 작업 단위 비용 미터 · 모델 라우팅

- **무엇** — 작업마다 지금까지 쓴 비용을 보여 주고 상한을 미리 정한다. 요청마다 속도 · 비용 · 품질을 따져 모델을 고른다. Glass 는 프로젝트마다 택시 미터 같은 비용 표시가 있다고 설명하고, 모델 라우터를 함께 내세운다(출시 글).
- **옴니스에 맞춘 모양** — 사람별 · 월별 상한은 이미 있다. 여기에 세션(실행) 머리에 「이 대화 n원」 을 보이고, 분류 · 요약 같은 가벼운 일은 작은 모델로 보낸다. 실행마다 비용은 이미 `AgentRun.costKrw` 에 쌓이고 있어 화면만 더하면 된다. 라우팅은 같은 과제로 모델을 비교한 실측(bench) 결과로 정한다.
- **선행 조건** — 모델별 단가표가 최신이어야 한다. 라우팅은 작은 모델의 품질을 먼저 bench 로 확인한다.
- **상태** — 아이디어.
