# 기능이 바뀌어도 e2e 가 목적을 지키게

상태: 2026-10-29 작업지시자 승인.

## Context

PR #108(떠 있는 nav)의 첫 CI 에서 e2e 7건이 깨졌다. 원인은 넷이었다.

| 깨진 것 | 드러난 약점 |
|---|---|
| ⌘K 팔레트 3건 | 「검색 버튼을 누른다」는 **위치**에 묶여, 버튼을 옮기자 「검색을 연다」는 목적까지 깨졌다 |
| 온보딩 「작성 중인 질문 보존」 | 테스트를 고칠 때 **무엇을 지키는지**를 놓쳐 성립할 수 없는 테스트로 바꿨다 |
| 업무 「상세」 시트 | 같은 글자가 한 군데 더 생겨 고르지 못했다 |
| 관계도 더블클릭 2건 | 진짜 화면 버그. e2e 가 제 몫을 했다 |

공통 원인은 **push 전에 e2e 를 한 번도 로컬에서 돌리지 않았다**는 것이다. 그리고 같은 날 폰에서 업무 화면이
깨진 것(칩이 44px 알약으로 부풂)은 e2e 가 잡지 못했다 — CI 는 PC 크기(`feature` 프로젝트)만 돈다.

## 이미 있는 것

- `pnpm run test:e2e:local`(`scripts/e2e-local.mjs`, 문서 `mydocs/manual/e2e-local.md`) — 임시 DB `omnis_e2e_*` 를 새로 만들고
  마이그레이션 · 데모 시드를 넣은 뒤 3002 포트 dev 서버에 feature 전체를 돌리고 지운다. **CI 와 같은 데이터 조건이 이미 로컬에 있다.**
  그런데 `AGENTS.md` 품질 게이트 표의 「사용자 흐름」 칸은 `pnpm run test:e2e (dev 서버가 떠 있는 상태에서)` 라고만 적혀 있어
  이 실행기를 가리키지 않고, 언제 돌려야 하는지도 없다
- `playwright.config.ts` 의 `mobile` 프로젝트(iPhone 13) — 정의만 있고 CI 도 스크립트도 부르지 않는다

## 할 일 (단계마다 커밋)

### 1. 게이트 규칙을 실행기에 맞춘다
- `AGENTS.md` 품질 게이트 표 「사용자 흐름」 → `pnpm run test:e2e:local -- --grep <태그>`. **화면(app/ · components/)을 바꾼 작업은 push 전에 해당 태그를 돌린다**
- 고친 테스트가 있으면 PR 본문에 「무엇을 지키는 테스트였고 왜 고쳤는지」를 적는다

### 2. 영역 태그와 「바꾼 파일 → 돌릴 태그」
- 각 `describe` 에 태그를 단다: `@nav` `@tasks` `@archive` `@search` `@onboarding` `@auth` `@reports` `@chat` `@mobile`
  (셸 `--grep` 과 CI 에서 다루기 쉽게 영문으로 둔다)
- `scripts/e2e-affected.mjs`: `git diff origin/main...HEAD` 의 경로를 태그로 바꿔 `--grep` 을 만든다.
  `pnpm run test:e2e:affected` = 그 태그만 `test:e2e:local` 로 돌린다. 경로 표는 스크립트 한 곳에 둔다
  - `components/layout/**` · `app/(main)/layout.tsx` · `app/globals.css` 처럼 모든 화면에 닿는 곳은 전체를 돌린다

### 3. 동작은 함수 하나로 (`tests/feature/_actions.ts`)
- `openSearch` · `gotoTab(이름)` · `openMy` · `openChatPanel` · `openOmnisAi` · `filterTasks` · `switchTasksView` · `replayTutorial`
- 각 spec 에서 버튼을 직접 찾던 곳을 이 함수로 바꾼다. 다음에 nav 가 바뀌면 이 파일만 고친다
- 함수 이름은 **사용자가 하려는 일**로 짓는다(「검색 버튼 클릭」이 아니라 「검색 열기」)

### 4. 테스트마다 「지키는 것」 한 줄
- 각 `test(...)` 위에 `// 지키는 것: …` — 사용자 입장의 약속 한 문장
- `tests/feature/README.md`(새로): 테스트를 고칠 때 이 줄이 그대로 성립하면 테스트를, 성립하지 않으면 **기능**을 의심한다

### 5. 폰을 게이트에 넣는다
- `mobile` 프로젝트를 `@mobile` 태그만 돌게 좁힌다(PC 용 테스트를 폰에서 돌리면 대부분 의미가 없다)
- 새 `tests/feature/mobile.spec.ts` `@mobile`: 390px 터치에서
  - 하단 nav 탭 넷 · 마이 동그라미 · 가로 넘침 없음 (업무 · 캘린더 · 아카이브 · 마이)
  - 업무 현황 띠 칩과 툴바 버튼이 **보이는 높이 40px 미만**이면서 누르는 자리는 44px (오늘 깨진 것)
  - 업무 툴바가 한 줄
- CI `e2e` job 에 `--project=mobile` 을 더한다

### 6. 블로킹 내비게이션 회귀 테스트 (`@tasks`)
- 업무 「멈춤」 칩을 누르면 주소가 바뀌고 건수가 바뀌며 **서버 재요청(RSC)이 0건**

## 검증

- `pnpm run verify`
- `pnpm run test:e2e:local` 전체 통과 (feature + mobile)
- **거부돼야 하는 경우를 보인다** (커밋하지 않고 로컬에서만):
  - 업무 칩에 `.touch-target` 을 되돌리면 `@mobile` 이 깨진다
  - 필터 칩을 서버 이동(`Link`)으로 되돌리면 6 이 깨진다
  - `components/layout/` 을 건드린 diff 에서 `e2e-affected` 가 전체를, `app/(main)/crm/` 만 건드린 diff 에서 `@archive` 만 고른다
- CI 통과

## 하지 않는 것

- 화면 스냅샷 비교(시각 회귀) — 데모 데이터가 날짜에 따라 바뀌어 매번 깨진다. 필요해지면 따로
- `scenario` · `legacy` 프로젝트 정리
- 운영 빌드(`next start`) 로컬 실행 — 운영 DB 에 붙는다. 빌드 경로는 CI 가 맡는다

## 브랜치

`feat/e2e-guard` 는 `feat/floating-nav`(PR #108) 위에 쌓는다 — 테스트가 새 nav 를 전제로 한다.
PR #108 이 먼저 머지되면 main 으로 rebase 한다.
