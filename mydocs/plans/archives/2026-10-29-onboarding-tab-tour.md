# 온보딩을 스포트라이트 하나로 — 탭별 안내 · 옴니스 시연

상태: 2026-10-29 작업지시자 승인. 대본 2 의 문서는 **지식 카드**, 예시는 위 「가벽 블라인드」 대로.

## Context

지금 온보딩은 두 단계다. 처음 들어오면 **풀스크린 8장면 영상**(`welcome-tour.tsx`)이 돌고, 끝나면
**스포트라이트 5장면**(`spotlight-tour.tsx`)이 실제 화면의 메뉴를 비춘다.
영상은 「채팅으로 업무를 만든다」 를 중심으로 짜여 있다. 이제 화면이 탭(채팅 · 업무 · 캘린더 · 아카이브) 위주로 바뀌었고,
핵심 기능은 「옴니스와 함께 업무를 시작한다」 이다.

## 작업지시자가 정한 것 (2026-10-29)

- 안내는 **스포트라이트로만** 한다. 풀스크린 영상은 새 랜딩페이지에 쓸 것이라 **파일은 남기고 온보딩에서만 뗀다**
- 장면 순서
  0. **간편 로그인** — 소셜 로그인(구글 · 카카오)은 누구인지 알아보는 데만 쓰고 계정 정보는 쓰지 않는다고 설명한다.
     **연결 버튼까지** 둔다
  1. **옴니스와 함께 업무를 시작해보세요** — 업무를 만드는 모션 그래픽
  2. **옴니스로 업무를 진행** — 옴니스가 문서를 만드는 과정의 모션 그래픽
  3. **업무 탭**
  4. **캘린더 탭**
  5. **아카이브 탭**
- 1 · 2 의 모션은 **채팅 화면 위에 직접** 그린다. **실제 컴포넌트**(말풍선 · 도구 사용 줄 · 제안 카드)를 쓰고, **모델은 부르지 않는다**
- NAS → 시놀로지 이름 변경은 별개 작업이다(`feat/nas-to-synology`). 이 안내의 문구는 「시놀로지」 로 쓴다

## 설계

### 장면 하나의 모양

```ts
type Stop = {
  id: string
  route?: string          // 이 장면에 들어갈 때 옮겨 갈 화면 (/chat/new · /tasks · /calendar · /omnis)
  target?: string         // 비출 data-onboarding 표식. 없으면 화면 가운데 설명창만
  title: string
  copy: string
  demo?: "create-task" | "write-doc"   // 채팅 대화 칸에서 재생할 대본
  social?: true            // 0번 장면: 연결 버튼
}
```

- 장면을 넘기면 `route` 로 `router.push` 하고, 화면이 그려지면 `target` 을 잰다(지금의 잼 코드를 그대로 쓴다)
- 탭 장면(3~5)은 그 탭의 nav 버튼과 화면 본문을 함께 비춘다 — nav 만 비추면 「무엇이 있는지」 가 안 보인다

### 0. 간편 로그인

- 비출 것 없이 가운데 설명창. 「구글 · 카카오로 간편하게 들어오세요. 누구인지 알아보는 데만 쓰고, 이름 · 메일 같은
  계정 정보는 가져다 쓰지 않아요」
- 버튼: 켜져 있는 제공자만(`/api/account/identities` 가 주는 목록 — 마이의 「연결된 계정」 과 같은 출처). 이미 연결된 것은
  「연결됨」. 「나중에」 로 넘어간다
- 연결 버튼은 구글 · 카카오 화면으로 나갔다 온다. **나가기 전에 「다음은 1번 장면」 을 sessionStorage 에 적고**, 돌아오면
  그 장면부터 잇는다. 온보딩 완료 여부(DB)는 그대로라 안내는 다시 뜬다
- 계정 정보 문구가 사실인지 구현 때 `lib/auth.ts` 의 signIn 콜백에서 저장하는 칸(provider · providerAccountId · email)을 보고
  확인한다. 메일을 저장하고 있으면 문구를 「연결 확인에만 쓴다」 로 맞춘다

### 1 · 2. 옴니스 시연 (대본 재생)

- `/chat/new`(옴니스 새 대화)로 옮겨 간 뒤, 대화 칸 위에 **시연 층**을 깐다. 시연 층은 실제 대화 칸과 같은 자리 · 같은
  컴포넌트로 그리지만 상태는 따로 들고, **API 를 부르지 않고 DB 에 아무것도 쓰지 않는다**
- 쓰는 컴포넌트: `omnis-room.tsx` 의 `MyMessage` · `OmnisMessage` · `LiveOmnis`(지금은 파일 안 함수 — export 만 한다),
  `ToolTrail`, `AgentCard`
- 대본 1 「업무 만들기」
  1. 입력칸에 한 글자씩: 「다음 주 금요일까지 가벽 블라인드 설치 견적 받아줘. 담당은 사원2」
  2. 보냄 → 내 말풍선
  3. 도구 줄: `구성원 목록` 실행 → 완료, `업무 만들기 제안` 실행
  4. 제안 카드(확인 대기): 업무 이름 · 담당 · 마감 · 체크리스트
  5. 「확인」 이 눌리는 표시 → 카드가 「실행됨」, 옴니스 답 「업무를 만들었어요」
- 대본 2 「업무 진행 — 문서 만들기」
  1. 입력: 「#가벽 블라인드 설치 지금까지 진행 상황 보고서 초안 써줘」
  2. 도구 줄: `업무 상세` → `사내 자료 검색` → `지식 카드 제안`
  3. 옴니스 답이 스트리밍되듯 문서 초안(제목 · 개요 · 진행 상황 · 다음 할 일)을 써 내려간다
  4. 제안 카드 → 「실행됨」
- 자동 진행: 대본이 끝나면 설명창의 「다음」 이 켜진다. 모션 감소 설정이면 타이핑 · 스트리밍 없이 끝 장면을 바로 보여 준다
- 폰: `/chat/new` 는 폰에서 대화가 전체 화면이라 같은 대본이 그대로 돈다

### 3~5. 탭

| 장면 | 화면 | 설명 |
|---|---|---|
| 업무 | `/tasks` | 현황 띠(멈춤 · 사람별), 목록 · 보드 · 관계도 보기, 업무를 누르면 스레드 |
| 캘린더 | `/calendar` | 업무 마감과 일정이 한 달력에. 웍스 캘린더와 이어진다 |
| 아카이브 | `/omnis` | 지식 카드 · 시놀로지 · 지식재산권 · 고객·견적 |

- 마지막 설명창 문구에 「안내는 마이에서 다시 볼 수 있어요」 를 붙인다. 지금의 「마이」 장면은 뺀다(작업지시자 목록에 없음)

### 떼는 것 · 남기는 것

- `onboarding-provider.tsx` — `video` 단계를 없애고 처음부터 스포트라이트로. 「다시 보기」 도 스포트라이트로
- `welcome-tour.tsx` · 그 CSS — **지우지 않는다**(랜딩용). 온보딩에서 import 만 뺀다
- DB `onboardingVideoSeenAt` — 스키마는 건드리지 않는다. 더 쓰지 않을 뿐이다. 이미 영상만 보고 안내를 안 마친 사람은 새 안내가 처음부터 뜬다
- `/api/onboarding` 의 `phase: "video"` — 받는 쪽은 그대로 둔다(옛 클라이언트 호환)

## 단계

1. 프로바이더에서 영상 떼기 + 장면 모델(`route` · `target`) + 탭 장면 3~5 → 검증: 로컬에서 새 계정으로 안내가 탭을 옮겨 다니며 비춘다
2. 0번 간편 로그인 장면 + 돌아왔을 때 이어 가기 → 검증: 로컬에서 카카오 연결 후 1번 장면부터 이어진다(로컬에 키가 없으면 버튼이 안 보이는 것까지)
3. 시연 층 + 대본 1 → 검증: 네트워크 탭에 `/api/agent` 요청이 없다. DB 의 방 · 업무 수가 그대로다
4. 대본 2 → 같은 검증
5. e2e 다시 쓰기 — `tests/feature/onboarding.spec.ts` 14건 중 영상 장면을 보는 9건은 지우고, 새 흐름(장면 순서 · 화면 이동 · 시연이
   쓰기를 하지 않음 · 모바일 · 모션 감소 · 다시 보기)으로 새로 쓴다. 계정 저장 · 거부 · 멱등성 시험은 남긴다
6. `pnpm run verify` · `narrow-audit` · PR → CI 통과 후 작업지시자 확인
