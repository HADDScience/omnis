# 2026-09-07 — 카톡 이식 파이프라인 · 결정 기록

> 이 문서는 구현이 끝난 뒤에 썼다. 작업지시자가 "파이프라인화 + 최신분 반영 + 품질 확인" 을 한 번에
> 지시했고 승인 게이트 없이 진행했으므로, 사전 계획서가 아니라 **무엇을 왜 골랐는지**의 기록이다.
> 절차는 [`import-tools/README.md`](../../../import-tools/README.md) 가 정본이다.

## 결정

### 1. AI 호출은 Gemini 가 아니라 `claude -p`

앱은 Gemini 무료 티어(하루 500호출, `lib/gemini-usage.ts`)를 실서비스 몫으로 쓴다.
이식은 한 번에 수백 세션을 읽히므로 그 예산을 건드리면 그날 옴니스 AI 가 멈춘다.
처음 633세션도 Claude 서브에이전트로 했고(방식 검증됨), 그 프롬프트를 transcript 에서 회수해
`prompts/classify.md` · `prompts/structure.md` 로 저장소에 넣었다. 이 CLI 는 `claude` 가 깔린 곳에서만 돈다.

버린 안: Gemini 로 통일 — 무료 티어 한도. Anthropic API 직접 호출 — 키 관리가 하나 더 늘고 `claude -p` 로 충분.

### 2. 분류는 병렬, 구조화는 순차

세션 분류는 세션끼리 독립이라 30개씩 동시 4개. 구조화는 N 라운드가 1..N-1 이 만든 프로젝트·업무를
맥락으로 받아야 3월에 생긴 과제에 5월 업무가 붙는다 — 병렬이면 같은 프로젝트가 이름만 다르게 흩어진다(처음 이식 때 실측).

### 3. 구조화 결과는 세션별로 캐시한다 (`structure/drafts.json`)

로컬에서 눈으로 본 카드와 프로덕션에 들어가는 카드가 같아야 한다. Claude 를 다시 부르면 조금씩 다른 카드가 나온다.
그래서 한 번 받은 결과는 세션 id 로 저장하고 어느 DB 에 적용하든 그것을 쓴다. 프로젝트는 id 와 함께 **이름**도 저장한다 —
다른 DB 에서는 id 가 다를 수 있다.

### 4. 분류는 1패스

처음엔 3패스 다수결이었다. CLI 는 1패스 — "애매하면 업무" 규칙이 놓치는 쪽보다 넘치는 쪽으로 기울고,
넘친 것은 구조화가 걸러 준다. 3패스가 필요해지면 그때 넣는다.

### 5. 임베딩은 마지막 단계에서 100건 묶음으로

"이식 중 부수효과 없음" 원칙은 그대로다. 다만 안 돌리면 옴니스 AI 가 이식 자료를 못 찾는다 —
처음 이식 뒤 채팅 9천 건 중 79건만 색인돼 있었던 것이 그 결과. `syncEmbeddings` 는 건당 1호출이라
채팅 수천 건이면 하루 한도를 한 번에 쓰므로, `syncEmbeddingsBatch` 를 `lib/embeddings.ts` 에 넣었다.
`--no-embed` 로 뺄 수 있다.

### 6. 첨부는 이름으로만 확실히, 시각은 ±3분

CSV 에는 `File: 이름.pdf` / `Photo` 만 남는다. 이름은 확실한 짝이다. `Photo` 는 이름이 없어
카톡이 저장 시 붙이는 파일명의 시각으로 찾는다. 못 맞춘 것은 붙이지 않고 목록으로 보고한다 —
엉뚱한 사진이 붙는 것보다 낫다. 톡 클라우드는 API 가 없어 경로가 아니다.

### 7. 프로덕션은 같은 CLI 에 `--target prod`

`.env.production.local` 의 Neon 주소를 읽고, `neon.tech` 가 아니면 멈춘다(스냅샷 스크립트와 같은 안전장치).
로컬 스냅샷에서 먼저 돌려 보고, 같은 명령에 플래그만 붙인다.

## 검증 기준 (실측은 working 문서)

- 새 CSV 파서가 처음 이식의 멱등성 키(본문 sha1)를 보존하는가 → 옛 CSV 재파싱 9,136건 전부 일치
- 같은 CSV 두 번 → 두 번째 0건
- 이식 전후 같은 질문 → 근거 적중 비교
