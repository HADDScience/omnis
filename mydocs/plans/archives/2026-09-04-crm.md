# CRM — 엑셀에서 옴니스로

지시: "`HADDScience_CRM_260527.xlsx` 참고해서 만들건데 UX 가 매우 편리하게 만들고 싶어"

## 지금 무엇이 있나

`HADDScience_CRM_260527.xlsx` — 시트 14개, 실데이터 약 100건.

| 시트 | 건수 | 성격 |
|---|---|---|
| 기관마스터 | 23 | 대학 14 · 기업 4 · 연구원 3 · 병원 2 |
| 컨택포인트 | 23 | 기관당 담당자 |
| HRP Membership | 9 | 활성이면 할인 400,000원 |
| 제품마스터 | 10 | 완제품 8 + 원료 2 (DNA) |
| 견적 | 13 | 총 공급가 39,951,550 · 실합계 42,186,705 |
| 샘플요청 | 15 | 소개경로가 다 다르다 (학회·지인·QR·전화) |
| 출고 | 23 | 판매 / 샘플 / 증정 |
| 재고 | 5 | 원료 입고만 |
| 원본_* 4개 | 25 | 이전 백업. 옮기지 않는다 |

**규모가 작다.** 성능 문제는 없다. 이 일은 처음부터 끝까지 **입력 편의성** 문제다.

## 엑셀이 아픈 지점 — 실측

설명서가 스스로 인정하는 것과, 데이터에서 실제로 드러난 것.

### 1. 사람이 등록 순서를 외워야 한다

> "⭐ 가장 먼저 등록" · "등록 순서 준수 — 기관마스터 → 컨택포인트 → HRP → 견적/샘플"

새 거래처 첫 주문이면 시트 **4개**를 순서대로 오간다. 순서를 틀리면 드롭다운이 비어 있다.

### 2. 드롭다운을 벗어나면 조용히 깨진다

샘플요청 15건 중 **4건이 "애드젠 (ADD GEL 1%)"** 이다. 제품마스터에는 없다 —
"애드젤"의 오타를 손으로 친 것이다. 15건 중 27%가 마스터와 안 맞는다.

(기관명 매칭은 23건 전부 깨끗했다. 드롭다운을 쓴 곳은 문제가 없다 —
**손으로 칠 수 있다는 것 자체가 문제**라는 뜻이다.)

### 3. 계산 결과를 사람이 지울 수 있다

> "❌ 자동 셀 수정 금지 — 녹색 글씨는 수식이 들어있어 직접 수정하면 안 됨"

규칙으로 막고 있다. 규칙으로 막는 것은 언젠가 깨진다.

### 4. 담당자 이름에 직함을 못 쓴다

> "✅ 박준혁  ❌ 박준혁 교수님"

이름 **문자열**로 시트 간 매칭을 하기 때문이다. 원본 데이터에는 "허채정 교수님",
"윤근영 선생님" 처럼 직함이 붙어 있었고, 옮기면서 직함을 떼야 했다.

### 5. 견적 한 장에 제품 하나

2025-12-12 한국뇌연구원 건이 **두 줄**로 쪼개져 있다 (ADD Gel + Lypophilized).
실제 견적서는 한 장에 여러 품목이 들어간다.

### 6. 재고와 출고가 끊겨 있다

재고 시트의 **총 출고량이 전부 0** 인데 출고 시트에는 23건이 있다.
설명서도 "재고 시트의 출고량은 별도 관리"라고 적었다.

## 무엇을 만드나

위 여섯 개를 **구조로** 없앤다. 규칙이나 안내문으로 막지 않는다.

| 아픈 지점 | 앱에서 |
|---|---|
| 등록 순서 | 견적 쓰다가 기관·담당자를 **그 자리에서** 만든다. 순서가 사라진다 |
| 오타 | 자유 입력이 없다. 검색형 선택 + "없으면 새로 만들기" |
| 계산 셀 수정 | 계산값은 화면에 보이기만 한다. 만질 수 있는 곳이 아니다 |
| 직함 | 이름과 직함이 별개 필드. FK 로 잇는다 |
| 1행 1제품 | 견적 1건 : 품목 N줄 |
| 재고-출고 단절 | 출고가 재고를 차감한다 |

### 화면

```
/crm                거래 흐름 한 눈에 — 견적·샘플·출고를 시간순 한 줄기로
/crm/orgs           기관 + 담당자 (한 화면. 기관을 펼치면 담당자가 딸려 나온다)
/crm/orgs/[id]      기관 상세 — 이 기관의 견적·샘플·출고·HRP 전부
/crm/quotes         견적 목록
/crm/quotes/[id]    견적 상세 — 품목 여러 줄, 합계 자동
/crm/samples        샘플요청 — 발송 여부를 목록에서 바로 토글
/crm/products       제품 + 단가
/crm/inventory      원료 입출고와 현재고
```

## 단계

1. **스키마 + 이식** — Prisma 모델 7개 · 엑셀 100건 이식
   → 검증: 건수·합계가 대시보드 수치(공급가 39,951,550 / 실합계 42,186,705)와 일치
2. **기관·담당자** — 목록 + 상세 + 즉석 생성
   → 검증: 기관 23 · 담당자 23 전부 표시, 새 기관을 화면 이동 없이 생성
3. **견적** — 품목 여러 줄, HRP 할인 자동, 합계 자동
   → 검증: 기존 13건 재계산 결과가 엑셀 값과 일치
4. **샘플요청 · 출고 · 재고**
   → 검증: 출고 23건이 재고를 차감, 현재고가 음수가 되지 않음
5. **거래 흐름 대시보드**
   → 검증: 대시보드 6개 지표가 엑셀과 일치

각 단계 끝에 커밋. `npm run verify` 통과.

## 정하지 않은 것 (작업지시자 판단 필요)

1. 옴니스 안 `/crm` 인가, 별도 앱인가
2. 1~5 를 다 하나, 핵심(1~3)부터 하나
3. 엑셀은 이후 어떻게 되나 — 완전 이전인가, 내보내기를 유지하나
4. "애드젠" 4건 — 애드젤 오타로 보고 합치나, 별도 제품인가
