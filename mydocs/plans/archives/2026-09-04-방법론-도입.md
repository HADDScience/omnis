# rhwp 의 AI 페어 프로그래밍 방식 도입 (완료)

지시: "https://github.com/edwardkim/rhwp — 이 레포에서 설명하는 AI 페어
프로그래밍 방식 도입해줘"

## 무엇을 가져오나

rhwp 의 방법론은 네 겹이다.

1. 얇은 부트로더 + 단일 정본 (`CLAUDE.md` → `AGENTS.md` → canonical 문서)
2. 세 원칙 (컨텍스트 유지 · 사람의 통제권 · 주기적 확인)
3. 타스크 사이클 (등록 → 계획 → 구현 → 검증 → 마감)과 그 산출 문서
4. 품질 게이트

`mydocs/` 문서 규약은 2026-09-02 에 이미 들어와 있다. 1~4 를 붙인다.

## 무엇을 안 가져오나

| rhwp 요소 | 뺀 이유 |
|---|---|
| `replay --capsule` 작업 영수증 · `lineage` · `audit` | rhwp CLI 고유 기능. 대응물이 없다 |
| `cargo clippy` 3단 게이트 | Rust 전용 |
| GitHub Issue 자동 채번 · 마일스톤 | 이 저장소는 Issue 를 쓰지 않는다 |
| 도구별 규칙 파일 8종 | Claude Code 단일 도구 |

쓰지 않을 절차를 미리 세우면 규율이 아니라 의식(儀式)이 된다.

## 단계

1. UX 규칙 11~30 을 `mydocs/manual/ux-rules.md` 로 → 검증: 규칙 20개 보존
2. `AGENTS.md` 작성, `CLAUDE.md` 를 부트로더로 → 검증: 줄수 감소, 링크 유효
3. `mydocs/manual/hyper-waterfall.md` 작성 → 검증: 뺀 것을 표로 명시
4. 타스크 사이클 폴더 + `npm run verify` → 검증: 실제로 돌려 출력 확인
5. `mydocs/README.md`·`ai-pairing.md` 갱신 → 검증: 낡은 사실 교정
