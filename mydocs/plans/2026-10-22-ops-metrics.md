## 무엇을 만드나

### 1. 가동률 — GitHub Actions 예약 작업

- `.github/workflows/uptime.yml` 이 30분마다 운영 주소 두 곳을 친다.
  - `/login`: 사이트(정적 페이지)가 응답하는가
  - `/api/health`: 서버 함수가 실행되는가
- 둘 중 하나라도 200 이 아니면 그 실행을 **실패로 끝낸다.** 실행 기록 자체가 측정 장부다.
- 가동률 = 성공 회차 ÷ 전체 회차. 장애 한 건 = 연속 실패 묶음 하나. 복구 시간 = 첫 실패부터 다음 첫 성공까지.
- `scripts/uptime-report.ts` 가 `gh run list` 로 이 셋을 센다.

#### 왜 이 방식인가

- **Neon 을 깨우지 않는다.** Neon 은 깨어 있던 시간만큼 과금된다([`2026-09-28-neon-wake-time`](../working/2026-09-28-neon-wake-time.md)). 30분마다 DB 를 치면 하루 48번 깨운다. 그래서 `/api/health` 는 DB 에 닿지 않는다. 대신 「DB 가 살아 있는가」는 재지 않는다. DB 장애는 Vercel 에러 묶음(2번)에서 본다.
- **GitHub 이슈를 열지 않는다.** 저장소가 공개라 이슈도 공개다. 실행 기록만으로 셋을 다 셀 수 있다.
- **비용 0원.** 공개 저장소의 표준 러너는 Actions 분을 세지 않는다. 시크릿도 필요 없다(공개 URL 만 친다).

#### 한계 (보고서와 이력서 문장에 그대로 적는다)

- GitHub 예약 작업은 제시간에 돌지 않을 수 있다. 몇 분 늦거나 건너뛸 수 있다. 그래서 가동률의 분모는 「30분 × 기간」이 아니라 **실제로 돈 회차**다.
- 30분보다 짧은 장애는 놓칠 수 있다. 복구 시간은 30분 단위로 거칠다.
- 공개 저장소에서 60일 동안 활동이 없으면 GitHub 이 예약 작업을 끈다. 12월 말까지는 커밋이 계속 있을 것이라 해당이 없을 것으로 본다.

### 2. 주간 에러 · 3. 월 비용 — 손으로 쓰는 장부

`mydocs/working/ops-log.md` 한 파일에 둔다. 코드는 바꾸지 않는다.

- **주간 에러 (매주 월요일):** Vercel 에러 묶음(최근 7일)을 옮긴다.
  - 옮기는 것: 묶음 이름, 건수, 처음·마지막 시각, 경로
  - 옮기지 않는 것: 표본 메시지. 업무명·사람 이름이 섞여 있다
- **월 비용 (매월 초):** GCP · Neon · Vercel 청구액을 한 줄씩 적는다.
  - 출처를 같이 적는다: 콘솔 청구서 금액인지, 배분 결정인지
  - 「GCP 40,000 + Neon 10,000」은 2026-10-07 에 정한 배분 결정이다(회사 인프라 월 상한 50,000원). 청구액이 아니라서 따로 표시한다.

Vercel 에러를 자동으로 옮기려면 Vercel 토큰을 GitHub 시크릿으로 등록해야 한다. 이번에는 하지 않는다. 주 1회 수작업이 시크릿 하나를 늘리는 것보다 싸다.

### 4. kpi-export 실패 처리

- `eventsSince()` 의 에러를 삼키지 않는다. 실패하면 non-zero 로 끝난다.
- 시작할 때 Prisma 클라이언트에 `kpiDaily` · `taskEvent` 가 있는지 먼저 본다. 없으면 「`npx prisma generate` 를 먼저 돌려라」는 메시지와 함께 실패한다.
  - 지금은 `TypeError: Cannot read properties of undefined (reading 'findMany')` 가 나와서 원인을 알기 어렵다.
- 원래 `catch` 가 있던 이유는 「마이그레이션 전 DB 에서도 숫자를 보려고」였다(커밋 43bc9ec). 운영(10/16)과 데모(빌드가 적용) 모두 마이그레이션이 끝났으니 그 경우는 더 없다.
