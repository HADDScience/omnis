# 2026-09-10 — 지식 카드를 AI 가 관리한다 (승인 대기)

작업지시자 결정: **지식 카드를 사람이 직접 쓰고 관리하는 것이 아니라, AI 가 업무 중 발생하는
변화를 직접 관리하고 갱신하게 한다.**

배경은 `mydocs/plans/2026-09-10-knowledge-cards.md` — 카드는 프로덕션에도 0건이고,
조회·수정·북마크가 전부 0이다. 사람이 채우는 구조로는 한 번도 채워지지 않았다.

## 이미 되는 것 — 업무 카드가 그렇게 돌고 있다

새로 발명할 것이 아니다. 옴니스는 **업무 카드를 이미 AI 가 채팅에서 다시 쓴다.**

```
사람이 채팅에 "#슬러그 D 길이 줄인 세 번째 안으로 확정합니다"
  → lib/chat-post.ts:130  rebuildTask(업무 정보 + 그 업무의 대화 전체)
  → AI 가 판정: complete · pause · resume · rebuild · info · none
  → rebuild 면 업무명 · 배경 · 기대결과 · 체크리스트를 새로 써서 저장
  → 관련자에게 알림 "업무 카드가 재구성되었습니다"
  → 임베딩 재색인
```

이 설계에서 배울 것이 넷이다.

| 특징 | 왜 그렇게 했나 |
|---|---|
| 트리거가 명시적 (`#멘션`) | 모든 메시지가 아니라 사람이 그 업무를 지목했을 때만 돈다. 비용과 오작동을 함께 줄인다 |
| 범위가 좁다 (그 업무의 대화만) | 엉뚱한 맥락이 섞이지 않는다 |
| 증분이 아니라 통째로 다시 쓴다 | 대화 전체를 다시 읽고 카드를 새로 만든다. 누적 오류가 쌓이지 않는다 |
| 판정을 먼저, 행동은 나중 | "무엇을 할 것인가" 를 먼저 정하고 그에 맞는 코드가 돈다 |

되돌리기 장치도 카드 쪽에 이미 다 있다.

- 카드를 쓸 때마다 `OmnisCardVersion` 이 남는다 (`app/api/omnis/cards/route.ts:38,99`)
- 복원 API `POST /api/omnis/[cardId]/restore`, 버전 목록 `GET /api/omnis/[cardId]/versions`
- 화면 `components/omnis/version-history.tsx`

즉 **AI 가 카드를 쓰게 만들 토대는 이미 서 있다.** 없는 것은 트리거와 판정뿐이다.

## 지식 카드로 옮길 때 달라지는 것 셋

1. **대상을 AI 가 골라야 한다.** 업무는 `#슬러그` 로 지목되지만, 지식은 "이 이야기가 어느 카드에 붙나"
   를 정해야 한다. 붙을 카드가 없으면 새로 만들지도 정해야 한다.
2. **트리거가 없다.** 사람이 "이건 지식이야" 라고 말해 주지 않는다. 대부분의 대화는 지식이 아니다.
3. **되돌리기가 더 중요하다.** 업무 카드가 틀리면 그 업무 하나가 이상해지고 끝난다.
   지식 카드가 틀리면 RAG 에 들어가 **AI 가 자기가 쓴 오류를 근거로 다시 답한다.** 오염이 굳는다.

## 구조 제안

### 언제 도나 — 트리거 셋

| 트리거 | 무엇 | 왜 |
|---|---|---|
| **업무 완료** | 완료된 업무의 대화 전체에서 지식을 뽑는다 | 가장 자연스러운 경계다. 일이 끝나면 거기서 확정된 사실이 생긴다. 하루 몇 건이라 비용도 작다 |
| **주간 배치** | 그 주에 오간 대화 중 어느 업무에도 안 묶인 것 | 업무 밖에서 정해지는 것(표기 규칙·조직·거래 조건)을 줍는다 |
| **사람이 지목** | 채팅에서 `#지식` 같은 표시, 또는 카드 화면의 「AI 로 갱신」 | 급할 때 사람이 당긴다. 선택 장치이지 주 경로가 아니다 |

매 메시지마다 돌리지 않는다. 채팅 12,764건 중 지식은 소수이고, 메시지 하나만 보면 맥락이 없다.

### 무엇을 하나 — 3단

```
1. 후보 판정   싼 모델(gemini-2.5-flash-lite)로 "이 대화에 회사 지식이 있나" 예/아니오 + 주제
                 없으면 여기서 끝. 대부분 여기서 끝난다
2. 대상 선택   주제로 카드를 검색(retrieveHybrid) → 붙일 카드 or "새 카드"
3. 갱신 제안   해당 카드 본문 + 근거 대화를 주고 새 본문을 쓰게 한다 (rebuildTask 와 같은 통째 재작성)
                 → 저장 · 버전 기록 · 출처 기록 · 알림
```

2단계에서 도구 라우팅(9-10 배포)을 그대로 쓴다. 카드를 찾는 것도 `search_knowledge` 다.

### 자가 오염을 막는 장치

이게 이 설계의 핵심 위험이다. 넷을 함께 건다.

1. **출처를 반드시 남긴다.** 카드 섹션마다 "어느 업무·어느 메시지에서 왔나" 를 기록한다.
   근거를 못 대면 쓰지 않는다. `OmnisCard` 에 `sourceRefs Json?` 를 더한다.
2. **사람이 쓴 것과 AI 가 쓴 것을 구분한다.** `OmnisCardVersion` 에 `authorKind`(human · ai)를 더한다.
   충돌하면 **사람이 쓴 문장이 이긴다** — AI 는 사람이 마지막으로 고친 섹션을 덮지 않는다.
3. **알림 + 되돌리기.** 갱신하면 관련자에게 알린다. 업무 카드 재구성과 같은 방식이다.
   틀리면 버전 목록에서 되돌린다.
4. **RAG 에 신뢰도를 싣는다.** AI 가 쓰고 사람이 아직 확인하지 않은 섹션은 검색 결과에
   "미확인" 을 달아 준다. 그래야 AI 가 자기 글을 정본처럼 인용하지 않는다.

### 씨앗 — 빈 서랍부터 채운다

AI 가 갱신하려면 갱신할 카드가 있어야 한다. 지금은 0장이다.
**이미 있는 자료로 초기 카드를 AI 가 만든다.**

| 재료 | 이미 있나 | 뽑을 것 |
|---|---|---|
| 채팅 12,764건 · 업무 594건 | 있다 (색인까지) | 표기 규칙, 거래 조건, 결정의 배경, 반복되는 설명 |
| NAS `HADD Science` 문서 | 목록·열기는 된다 | 회사 소개문, 제품 설명, 실험 프로토콜, 사내 규정 |
| `hadd-ecm-domain` 스킬 | 있다 | 제품 4종(애드젤·라이브젤·뉴로힐·비보젤), ECM 기술 설명 |

업무 594건을 한 번 훑어 초기 카드를 만드는 배치가 1단계다. 이게 끝나면 그 뒤로는 트리거가 유지한다.

### 카테고리도 바꾼다

지금 3개(기업정보 · 인력현황 · 지식재산권)는 전부 "세는 것" 의 이름이라 서술이 들어갈 자리가 없다.
`mydocs/plans/2026-09-10-knowledge-cards.md` 의 안 — 회사 소개 · 제품 · 기술 · 표기/브랜드 · 사내 규정 · 지원서 상용구.

## 비용 (9-09 벤치 단가 기준)

| 단계 | 모델 | 건수 | 건당 | 합 |
|---|---|--:|--:|--:|
| 후보 판정 | 2.5-flash-lite | 하루 20 (완료 업무 + 배치) | 0.3원 | 6원/일 |
| 갱신 | 3.8-flash low | 하루 2 | 5원 | 10원/일 |
| **운영 합계** | | | | **약 16원/일 · 월 480원** |
| 초기 씨앗 배치 | 3.8-flash low | 업무 594 | 5원 | 약 3,000원 (한 번) |

옴니스 질문이 문항당 10.4원인 것과 비교하면 작다. 비용은 이 결정의 장애물이 아니다.

## 단계

| | 무엇 | 드는 일 |
|---|---|---|
| 1 | 카테고리 교체 + 씨앗 배치 (업무 594건 → 초기 카드) | 2일 |
| 2 | 업무 완료 트리거 + 판정·대상 선택·갱신 3단 | 3일 |
| 3 | 출처·저자 구분·미확인 표시 (오염 방지 4종) | 2일 |
| 4 | 주간 배치 + 화면(갱신 이력·되돌리기 노출) | 2일 |

3번을 2번보다 뒤에 두지 않는 것이 좋다. 자동 갱신을 켜는 순간부터 오염이 시작되므로,
2와 3을 한 배포로 묶는 것을 권한다.

## 정해진 것 (2026-09-14)

**제안으로 시작하고, 수락 기록을 모아 수락이 많으면 자동으로 넘긴다** — 작업지시자 결정.

구현한 기준 (`lib/card-proposals.ts`, 전부 환경변수로 조절).

| 값 | 기본 | 환경변수 |
|---|--:|---|
| 자동 전환에 필요한 판단 수 | 20 | `CARD_AUTO_MIN_DECIDED` |
| 수락률을 세는 최근 표본 | 50 | `CARD_AUTO_WINDOW` |
| 자동 전환 수락률 | 0.8 | `CARD_AUTO_MIN_RATE` |
| 미처리 제안 상한 (넘으면 새 제안을 멈춘다) | 30 | `CARD_MAX_PENDING` |
| 강제 켜기/끄기 | 자동 | `CARD_AUTO_APPLY=on\|off` |

수락률은 **사람이 판단한 것만** 센다. 자동 적용된 것은 표본에 넣지 않는다 — 그것까지 성공으로 세면
한번 켜진 자동 모드가 스스로를 정당화한다. 다만 자동 적용을 사람이 되돌리면 거절로 센다.
그래서 틀리기 시작하면 수락률이 떨어져 **스스로 제안 모드로 돌아간다**. 저장된 켬/끔 플래그는 없다.

## 남은 결정
1. **카드를 지우는 것도 AI 가 하나.** 권고는 아니오. 낡은 섹션은 표시만 하고 지우기는 사람이. (미정)
2. 씨앗 배치를 업무 594건 전부로 돌릴지, 최근 것부터 나눠 돌릴지. (미정 — 지금은 `--limit 30` 기본)
