# 카톡 이식 — 수기 사본 건너뛰기 · 손으로 만든 업무도 맥락에

## 왜

9/5 이후 카톡 업무 대화 일부를 정우창이 구성원 계정으로 바꿔 가며 옴니스에 손으로 옮겼다.
이 사본은 `sourceId` 가 없어 이식 도구의 멱등 키로 걸러지지 않는다.
그대로 이식하면 같은 말이 두 번 들어간다.

실측(2026-10-01, 운영 DB 읽기 전용): 9/7 이후 카톡 1,230행 중 옴니스에 사본이 있는 것은 약 40건이다.
날짜로 자르면(`--since`) 손으로 옮기지 않은 1,000여 건이 빠지므로 **전부 넣고 사본과 짝이 맞는 것만 건너뛴다** (사용자 결정).

또 4단계 구조화는 AI 에게 기존 업무로 `kakao-task:` 카드만 보여 준다.
손으로 만든 업무(`#옴니스-및-연혁-업데이트` 등)를 모르니 같은 일로 카드가 한 장 더 생긴다.

## 무엇을

1. **사본 짝 맞추기** (`import-tools/hand-copies.ts`, 3단계에서 사용)
   - 같은 작성자 · 카톡 시각 ≤ 사본 시각 ≤ 카톡 시각 + 3일 · 정규화한 본문이 같거나, 8자 이상이면 한쪽이 다른 쪽에 들어 있음
     (옮기며 카톡 여러 줄을 한 글로 합친 경우가 많다)
   - 정규화: 앞의 `/업무` · `#슬러그` · `@이름` 과 끝의 `[첨부: …]` 를 떼고 공백을 모두 지운다
   - 8자 미만의 짧은 말은 완전히 같을 때 가장 가까운 하나와만 짝짓는다 — "네" 가 여러 번 걸리지 않게
   - 짝이 맞은 카톡 메시지는 넣지 않는다. 짝을 못 찾은 사본은 목록으로 보고만 한다
2. **구조화 맥락** — `priorTasks` 에서 `kakao-task:` 조건을 뺀다. 프롬프트 문구도 맞춘다
3. **검증** — `scripts/verify-kakao-hand-copies.ts`: 짝이 맞아야 하는 경우와 **맞으면 안 되는 경우**(다른 작성자 · 사본이 카톡보다 앞섬 · 3일 넘음 · 사본 하나에 카톡 둘)

4. **기존 업무에 이어 붙이기** — 로컬 1차 실행에서 새 카드 43장 중 6장이 손으로 만든 업무와 같은 이름,
   3쌍이 서로 같은 일이었다. 맥락에 기존 업무를 보여 주기만 해서는 카드가 줄지 않는다.
   구조화 결과에 `continuesTask`(이어지는 업무 이름)를 받아, 이름이 있으면 새 카드 대신 그 업무 스레드에
   메시지를 붙인다. 메시지가 이미 업무에 붙은 세션은 끝난 세션으로 본다.

## 하지 않는 것

- 수기 사본 삭제 — 손으로 만든 업무의 스레드가 사본으로 되어 있다

## 순서

1. 구현 + 검증 스크립트 → `pnpm run verify`
2. 운영 대상 `--dry` 로 건너뛸 수 · 넣을 수 · 짝 못 찾은 사본 확인 (DB 에 쓰지 않음)
3. 로컬 스냅샷에 실제 이식 → 생긴 카드 목록을 사용자가 검토
4. 승인 뒤 `--target prod`
