# 아카이브 › 인증 탭 (2026-11-28)

## 왜

인증 · 가점은 회사 정보 화면 아래 목록(#264 · #272)이었다. 따려는 인증은 국가과제처럼 마감 · 담당 · 준비물이 있는 일인데,
그 목록은 「보유 · 후보 · 자격 안 됨」 상태 칩과 메모뿐이라 일의 진행을 담지 못했다. 공고 가점(#287 · #291)을 모은 뒤로는
「이 인증을 따면 어느 공고에서 몇 점」 을 거꾸로 볼 수 있게 됐다.

**이 화면은 공통 층과 별개의 맞춤 화면이다.** 공통 층(계획서 `2026-11-27-ontology-phase1.md`)의 유형으로 등록하지 않는다.
다만 P9 에서 유형(`cert`)으로 등록할 수 있게 칸 키를 `lib/certs.ts` `CERT_FIELDS` 로 고정했다.

## 무엇

- **단계**: 후보 → 준비 → 신청 → 심사 중 → 보유 → 갱신 필요 → 만료, 어느 단계에서든 중단(`CERT_STAGES`).
  - 기존 enum `CertStatus` 를 text + CHECK 로 바꿨다(#274 국가과제와 같은 방법, `20261128100000_cert_stages`). 칼럼 이름은 `status` 그대로다.
  - 옛 값은 키가 같고, `NOT_ELIGIBLE`(자격 안 됨)만 `STOPPED`(중단) + 사유 「자격 안 됨 — 판정 이유」 로 옮긴다.
  - 옮기는 인증마다 활동 기록 `company.certification.stage_migrated` 를 남긴다. 사람 고침(`…updated`)과 action 이 달라, 이식의 사람 손질 보호가 사람 수정으로 읽지 않는다.
- **칸**: 인증명 · 발급 기관 · 접수 마감(시각까지) · 담당(한 사람) · 취득일 · 유효기간 · 메모 · 준비물(체크리스트) · 근거(채팅 글 · 파일 · 링크).
  - 근거는 글 본문을 복사하지 않고 그 방으로 잇는다(방 권한을 따른다).
- **목록 · 보드 전환**: 보드는 국가과제 보드(#280)에서 빼낸 `components/ui/stage-board.tsx` 를 같이 쓴다. 국가과제 보드도 이것으로 바꿨다(겉모양 · 보내는 값 · data 속성 그대로).
- **제자리 편집**: #272 의 `InlineField` · `useFieldSaver` — 칸 하나씩 PATCH, 고치기 전 값을 `expect` 로 붙여 그새 바뀌었으면 409. 충돌 확인에 시각(`minute`) · 목록(`json`) 종류를 더했다.
- **이 인증을 따면**: `bonusForCert` — 같은 인증 키(`CERT_KEYS`, NEP · NET 키를 더했다)의 가점 항목이 있는 접수 중 공고와 점수.
- **공고 가점표 → 인증 탭**: 우리 상태가 없음인 항목을 누르면 「인증 탭 후보로 올리기」(인증이 없을 때) · 「인증 탭에서 보기」(있을 때).
  - 가점표의 우리 상태 메모는, 중단이면 사유 앞부분(「자격 안 됨」)이다.
- **도구**: `list_certifications`(이름 유지 · 단계 · 담당 · 진행 중 · 공고 가점 거꾸로), 새 `get_certification`, `update_certification`(단계 · 사유 · 마감 · 담당 · 준비물 · 근거 링크), 새 `add_certification`.
- **회사 정보**: 인증 구역(`#certs`)은 단계별 건수와 이 탭으로 가는 링크만 남겼다. 회사 정보 화면의 다른 부분은 바꾸지 않았다.
- **넣기 스크립트**: `scripts/add-certification.ts --spec <명세.json>` — 손으로 정리한 인증 한 건을 넣거나 맞춘다. 명세는 저장소 밖에 둔다(사람 · 방 이름). 파일은 올리지 않고 옴니스 파일 id 로 받는다.

## 하지 않은 것

- 공통 층 유형 등록(P9)
- 인증마다 담당 여러 명(국가과제는 여러 명이다 — 지금 쓰임은 한 명)
- 근거 채팅 글을 화면에서 고르는 창(지금은 링크만 화면에서 더하고, 글 · 파일은 스크립트 · 도구로)
