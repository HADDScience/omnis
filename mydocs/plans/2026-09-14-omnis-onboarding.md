# Omnis 자동 재생 온보딩

상태: 2026-09-14 사용자 승인 후 구현·전용 검증 완료, 사용자 검토 대기. 전체 E2E는 데모 계정 부재로 미통과. 보고서: `mydocs/working/2026-09-14-omnis-onboarding.md`.

## 목표와 확인한 근거

사용자가 요청한 8장면을 자동 재생하고, 마지막 「업무 시작하기」에서 원래 서비스 화면으로 돌아와 실제 메뉴·버튼·영역을 스포트라이트로 안내한다. 계정별 첫 Omnis 접속에 표시하며 프로필에서 다시 볼 수 있다.

- 참고: `~/work/hadd-hub/components/onboarding/welcome-tour.tsx`, `welcome.css`, `welcome-gate.tsx`. 중앙 타이포그래피, 블러 전환, 여백, 주변 부유 도형을 참고한다. Hub는 클릭 전환·브라우저 저장 방식이므로 Omnis 요구에 맞춰 자동 전환·계정 저장으로 바꾼다.
- Omnis: `app/globals.css`의 primary 색상과 라이트·다크 토큰, 기존 로고·Hugeicons·업무 카드 표현을 사용한다. 예시 화면은 데모 표시를 하고 실제 업무를 생성하거나 변경하지 않는다.
- 프로필 메뉴는 `components/layout/app-sidebar.tsx`, 인증 이후 공통 진입은 `app/(main)/layout.tsx`다.
- User에는 온보딩 이력이 없다. `workspaceLayout`은 전용 PUT에서 전체 교체하므로 온보딩 상태를 섞으면 유실된다. 전용 nullable 시각 필드를 추가한다.
- MCP 서버와 OAuth는 이미 있다(`mydocs/tech/omnis-mcp.md`). 개인 토큰 발급 확대는 이 작업에 포함하지 않는다.

## 화면 구성

| 장면 | 문구·내용 | 연출 / 기본 시간 |
|---|---|---|
| 1 | 안녕하세요. Omnis 입니다. | 로고와 큰 인사 문구 등장 / 4초 |
| 2 | Omnis를 이용하여 업무하는 법에 대해서 알아볼게요. | 업무·대화·지식이 연결되는 구성 / 5초 |
| 3 | Omnis로 업무지시하기 | `/` 커맨드 → 파일 첨부 → AI 자동생성 → 업무 카드 순서 / 12초 |
| 4 | Omnis로 업무 확인하고 완료하기 | 업무 언급·스레드 대화 → 완료 보고 → 상태 변화 / 12초 |
| 5 | Omnis로 업무 추가지시하기 | 업무 언급·스레드의 추가 요청 → 업무 내용·상태 갱신 / 10초 |
| 6 | Omnis MCP 등록하여 AI 활용하기 | 프로필 메뉴의 무지개 테두리 MCP 버튼 → 연결 안내 / 9초 |
| 7 | CRM, 지식재산권 등 다양한 도구를 활용해 회사 자원을 활용해 보세요. | 도구 미리보기와 연결선 / 7초 |
| 8 | 회사의 지식을 하나로, | 「업무 시작하기」 버튼. 자동 종료하지 않고 대기 |

시간은 실제 재생 가독성을 보고 조정한다. 화면 클릭으로 장면을 넘기지 않는다. 진행 표시·일시정지/재생·건너뛰기를 제공하고, 비활성 탭에서는 타이머를 정지한다. 모션 감소 설정에서는 움직임·블러를 줄이고 읽을 시간을 유지한다. 영상 파일 대신 서비스 안에서 재생되는 UI 애니메이션으로 구현한다.

스포트라이트는 업무 메뉴 → 업무 지시 진입점·채팅 입력 → 업무 대화·스레드 영역 → Omnis AI → 회사 도구 → 프로필의 MCP·튜토리얼 메뉴 순서로 실제 보이는 요소를 안내한다. 기본 자동 진행에 일시정지·건너뛰기를 제공한다. 숨겨진 패널은 필요한 단계에서 열고 종료 시 복원한다. 해당 경로에 없는 대상은 공통 진입점을 안내하고, 모바일은 메뉴를 여는 단계로 대응한다. 원래 URL과 사용자 입력을 보존한다.

## 계정 상태와 MCP 동작

- User에 `onboardingVideoSeenAt`, `onboardingCompletedAt`을 nullable DateTime으로 추가한다. 영상 종료/건너뛰기와 스포트라이트 종료/건너뛰기를 별도로 저장한다. 영상만 마친 뒤 다시 접속하면 스포트라이트부터 이어간다.
- 기존 계정·새 계정 모두 이력 없음에서 시작하여 적용 후 첫 접속에 표시한다. 마이그레이션·Zod·기존 계정 null 유지의 백필 정책/스크립트를 같은 커밋에 둔다.
- API는 활성 로그인 계정의 상태만 읽고 쓴다. 클라이언트가 보낸 사용자 ID를 신뢰하지 않는다. 반복 완료 요청은 멱등적으로 처리한다.
- 저장 실패는 안내하고 재시도할 수 있게 하되 서비스 진입을 막지 않는다. 브라우저 저장만으로 계정별 완료를 판단하지 않는다.
- 프로필의 「온보딩 튜토리얼」은 완료 여부와 무관하게 영상부터 다시 재생한다.
- 「Omnis MCP 등록」에는 Magic UI의 무지개 테두리 컴포넌트를 적용한다. 구현 시 공식 소스를 확인하고 기존 Omnis 테두리·테마와 색감을 맞춘다.
- MCP 메뉴는 서버 주소 복사와 OAuth 커넥터 등록 절차를 담은 실제 동작하는 안내창을 연다. 외부 AI 앱 등록을 자동 완료했다고 표시하지 않는다. API URL은 기존 base-path 유틸리티와 MCP 설정을 따른다.

## 수행 순서와 검증

1. **자동 재생 장면 구현** — 8장면, 실제 기능과 일치하는 데모, Omnis 테마, 타이머·접근성. 검증: 클릭 없이 순서대로 전환, 마지막 버튼 대기, 일시정지·비활성 탭·모션 감소·모바일.
2. **계정별 표시 연결** — Prisma 필드·마이그레이션·Zod·백필 스크립트, 상태 API, main layout의 온보딩 게이트. 검증: 첫 접속·재접속·다른 브라우저·다른 계정, 비로그인·타 계정 조작 거부, 저장 실패.
3. **프로필 메뉴와 MCP 안내 연결** — 다시 보기와 Magic UI 테두리 MCP 메뉴. 검증: 다시 보기, 주소 복사 성공/실패, 키보드·모바일 메뉴, 실제 OAuth 구성과 안내 일치.
4. **실제 화면 스포트라이트 연결** — 안정적인 대상 속성, 패널·메뉴 열기와 복원, 화면 크기·스크롤 변화 대응. 검증: 마지막 CTA 후 시작, 모든 대상 위치, 없는 대상 처리, 중단·종료, URL·입력 보존.
5. **통합 검증·결과 기록** — `npm run verify`, `npm run build`, dev 서버에서 `npm run test:e2e`, UX 규칙 11~30 점검. API의 인증 거부 사례와 첫 접속 흐름을 포함한다. 명령과 실측 출력, 화면 확인 결과를 `mydocs/working/2026-09-14-omnis-onboarding.md`에 기록한다.

단계별 커밋. 로컬 DB 대상 확인 후 마이그레이션 검증. 운영 DB 적용·push·PR·배포는 별도 승인 대상이다.

## 사용자 화면 검토 후 승인된 보완

- 화면 잘림 제보: 헤더·재생 컨트롤·최종 CTA의 공간을 고정하고 설명 장면만 남은 높이에 맞춘다. 작은 화면에서 아래로 밀려난 버튼을 찾지 않게 하기 위해서다.
- 채팅 타이핑/전송 연출 요청: 업무 지시·완료 보고·추가 지시 모두 입력창 타이핑 → 전송 버튼 반응 → 말풍선 등장 → 업무 갱신 순서로 표현한다.
- 스포트라이트 정교화 요청: 대상의 실제 보이는 경계·스크롤 클리핑·확대 배율을 반영한다. 설명창의 실제 높이로 겹치지 않는 면을 골라 연결선을 표시하고, 자동 진행을 유지하면서 이전·다음·일시정지를 제공한다.
- 검증: 작은 창/배율 회귀, 데모 실제 쓰기 없음, 강조 영역 오차·설명창 비겹침·수동 탐색을 추가한다.
