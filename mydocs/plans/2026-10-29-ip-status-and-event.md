# 지식재산권 단계 → 상태 5개 + 사건

**한 줄:** 옛 단계 12개에 섞여 있던 「도달한 지점」과 「그 사이에 일어난 일」을 나눈다.
상태 정의는 작업지시자가 확정했다(2026-10-29).

## 왜

- 「심사중」이 어느 지점인지 알 수 없다. 우선심사신청을 기록하며 단계를 「심사중」으로 바꿨다가
  「출원」으로 되돌린 일이 있었다(2026-10-29).
- 의견제출통지·보정서제출은 출원 상태에서 일어나는 사건인데 단계처럼 쓰였다.
- 출원한 건에 「검토의견」을 기록하면 단계가 뒤로 갔다.

## 정의

| 상태 | 뜻 | 열림 | 들어가는 조건 |
|---|---|---|---|
| 출원전 | 아직 특허청에 내지 않았다 | 열림 | 기본값 |
| 출원 | 냈고 결과가 확정되지 않았다 | 열림 | 출원번호가 생겼다 |
| 등록 | 권리가 생겼다 | 닫힘 | 등록번호가 생겼다 |
| 거절 | 거절이 확정됐다 | 닫힘 | 거절결정에 불복하지 않아 확정 |
| 포기 | 우리가 멈췄다 | 닫힘 | 출원 전 중단·취하·등록료 미납 소멸·대체 |

특허결정·출원공고·등록료 납부 대기·거절결정에 다투는 중은 아직 「출원」.

## 설계

| 결정 | 이유 |
|---|---|
| `status_options` 는 상태 5개만, 옛 단계·새 사건은 `event_options` | 대장의 외래키가 상태만 받게 — 유령 단계가 대장에 못 들어간다 |
| `progress_entries.stage` 칸 이름은 두고 뜻만 「사건」 | 운영 마이그레이션과 머지 사이에 옛 코드가 돌아도 깨지지 않는다 |
| `progress_entries.status` = 명시한 상태(NULL 허용) | NULL 은 「사건·번호 규칙에 맡김」. 옛 기록은 표대로 채워 재계산이 지금 대장과 같게 |
| 상태를 옮기는 사건은 출원·등록·거절확정·포기(·옛 포기·중단) 뿐 | 「상태를 바꾸지 않는 사건」을 정의로 못박는다 |
| 번호 자동 전환: 등록번호 처음 → 등록, 출원번호 처음 → 출원 | 형식 검사(`NN-YYYY-NNNNNNN`, `NN-NNNNNNN`)를 건다. 출원번호 칸에 대리인 사건번호가 들어간 건이 있다 |
| 자동 전환은 출원일·등록일을 채우지 않는다 | 메일 날짜가 출원일이 된 2026-10-28 함정과 같다. 응답이 날짜를 채우라고 알려 준다 |
| 출원일 latch 는 「출원」 사건, 등록일은 「등록」 사건에서만 | 상태 명시만 한 기록은 날짜를 모른다 |
| 판단은 `ip.entry_status()` 한 곳 | 트리거와 `rebuild_ledger` 가 같은 함수를 부른다 |
| 옛 단계 값으로 오는 호출은 `resolveStatusEvent`(lib/ip-data.ts)가 번역 | 표대로 상태+사건으로 나누되, 옛 값이 지금보다 앞 상태를 가리키면 상태는 그대로(출원한 건의 「검토의견」) |

## 단계

1. 마이그레이션 `20261029100000_ip_status_and_event` — 운영 사본에서 재계산 동일성 확인
2. 서버: `lib/ip-data.ts`·`lib/ip-mcp.ts`(add_progress·list_stages·correct_ip·create_ip·read_guide·get_ip·list_todo)·웹 API·옴니스 질문·지식 색인
3. 검증 스크립트: `verify-ip-dates.ts` 에 상태·사건·번역 시험, `verify-ip-mcp.ts`·`verify-ip-import.ts` 갱신
4. 화면: 옛 화면(hadd-ip-platform)은 별도 저장소. 2026-10-29 뒤 main 에 들어온 `/ip` 는 이 PR 에서 상태 5개에 맞춘다
5. 운영 — 작업지시자 승인 뒤: 백업 → `migrate deploy` → 머지 → 번호 칸이 잘못된 거절 건 정정(correct_ip) → `rebuild_ledger` 동일성

## 마이그레이션 이름을 옮기지 않는 이유 (2026-11-04)

이름이 main 의 뒤 마이그레이션들보다 앞서지만 그대로 둔다.

- 데모 프로젝트의 프리뷰 빌드는 `prisma migrate deploy` 를 돌리고 프리뷰·운영이 같은 데모 DB 를 쓴다. 2026-10-29 프리뷰가 이 이름으로 이미 적용했다.
  이름을 바꾸면 데모 DB 에서 같은 SQL 이 다시 돌아 `CREATE TABLE` 에서 실패하고, 실패 기록(P3009)이 데모 배포 전체를 막는다.
- 운영 사본에서 뒤 마이그레이션이 모두 적용된 상태에 이 이름을 `migrate deploy` 로 적용해 통과했다. 뒤 마이그레이션 중 `ip` 스키마를 건드리는 것은 없다.
- 같은 이유로 `migration.sql` 내용도 고치지 않는다.
