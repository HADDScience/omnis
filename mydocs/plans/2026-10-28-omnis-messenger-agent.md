# 첫 화면을 옴니스 메신저로 — 채팅방 + 에이전트

상태: 2026-10-28 초안. 작업지시자 검토 대기. 스키마 변경 · 운영 마이그레이션 · 벤더 비용이 들어가
AGENTS.md 타스크 사이클 2단계(승인)를 거친다.

## 왜

Omnis 의 정의가 「채팅 기반 사내 지식 관리 에이전트」로 바뀌었다(2026-10-28).
로그인하면 업무 화면이 아니라 **옴니스와의 대화**가 먼저 보여야 하고, 사용자는 거기서
궁금한 것 · 하고 싶은 업무 · 회사 일 전반을 이야기한다. 화면은 사내 메신저처럼 보이고,
그 안의 대화가 사내 지식으로 쌓인다.

## 작업지시자가 정한 것 (2026-10-28)

| 항목 | 결정 |
|---|---|
| 화면 | 카톡처럼 왼쪽에 **채팅방 목록**, 가운데 대화. 채팅방 하나 = ChatGPT 의 세션 하나 |
| 방 종류 | 옴니스와 **1:1 방**도, 팀원을 초대한 **단톡방**(옴니스 포함)도 만든다 |
| 기존 채팅 | 「전체」 팀 채팅은 **전사방**으로, 업무 스레드는 **업무방**으로 목록에 들어온다. 메시지는 옮기지 않는다 |
| 대화 단위 | 대화 여러 개. 주제마다 새 방 |
| 실행 | 한 질문 한 답이 아니라 **여러 단계로 실제 작업해 결과물을 낸다.** 쓰기는 **제안 → 사용자 확인** 뒤 실행 |
| 결과물 | 업무 · 기록 작성, 문서 초안, 파일 생성(docx · xlsx · pptx), 대화 → 지식 정리. 일반 에이전트가 하는 일 전반. 참고: codegate folding |
| 엔진 | **벤더를 실측 비교해서 정하고, 회사에 월 얼마를 요구할지 산정한다** |
| 옴니스 호출 | 옴니스가 있는 방에서는 **직접 언급(`@옴니스`)할 때만** 답한다. 늘 듣다 끼어들면 신뢰가 떨어지고 토큰이 샌다 |
| 단톡방 범위 | 이번에는 **사람끼리의 단톡방만** 만든다. 옴니스가 들어간 단톡방은 뒤로 미룬다 |
| 방 만들기 | **구성원 누구나** |
| 순서 | **0단계(벤더 실측)부터** 시작한다 |
| 벤더 | **한 벤더에 묶지 않는다.** 3사 모델을 계속 벤치하고 우리 과제에 가장 맞는 모델로 갈아 끼운다. 지금 주 모델은 gpt-6.1-sol (0단계 실측 1위, `working/2026-10-28-agent-bench.md`) |
| 회사 요청액 | 에이전트만이 아니라 **임베딩 · 카드 생성 등 AI 비용 전부를 포함**한 금액 |
| 라우터 | 이번 건은 **Jev 없이** 에이전트 SDK 하나로 간다 (0-b · 0-c 실측: luna/sol 라우팅 절감이 작고 test 에서 완수율이 깎임) |
| 에이전트 SDK | **Vercel AI SDK 7** (`WorkflowAgent`). 모델은 **각 사 키로 직접** 연결(`@ai-sdk/openai` · `anthropic` · `google`) — 토큰은 각 사가 청구, Gateway 는 쓰지 않는다 |
| 채팅 속 비밀번호 | 운영 채팅의 비밀번호 글(공용 PC · 게스트 와이파이)은 **그대로 둔다.** 대신 에이전트가 그것을 지식 카드 · 기록 · 다른 방으로 옮기지 않게 막는 것은 3단계 몫이다 |
| Vercel 플랜 | 지금 Hobby. **11월 중 Pro 전환 예정.** Hobby 는 상업적 사용 불가 · Workflow 이벤트 월 5만 개 포함 |

요청 하나가 사용자를 기다리며 열려 있을 수 없다 → 아래 「실행 모델」.

## 실행 모델

```
사용자 글 ─→ POST /api/rooms/{id}/messages
              └─ 에이전트 실행(AgentRun) 시작, SSE 로 단계 중계
                   도구 호출 ─ 읽기 ─→ 바로 실행, 다음 턴
                            └ 쓰기 ─→ 제안 카드(AgentStep: PENDING_APPROVAL, 계획 해시) 저장
                                       실행을 **멈추고 요청을 끝낸다**
사용자 [확인] ─→ POST /api/agent/steps/{id}/approve
              └─ 해시 확인 → 도구 실행 → 같은 실행을 이어서 재개(SSE)
```

- 실행 상태(메시지 · 도구 호출 · 결과)를 **DB 에 남기고** 요청마다 거기서 이어 간다. 새로고침 · 재접속에도 끊기지 않는다
- 엔진은 **벤더 중립 루프**로 만든다(`bench/providers.ts` 어댑터를 운영 코드로 올린다). 벤더는 0단계 실측으로 고르고 환경변수로 바꾼다
- 쓰기 도구는 MCP 쓰기 도구와 **같은 함수**를 부른다(화면 · MCP · 에이전트가 한 길)
- 옴니스는 **요청한 사람의 권한으로** 움직인다. 지식재산권 도구 같은 구성원 전용 도구도 그대로 막힌다

## 단계

### 0. 벤더 실측 · 예산 산정 (1 · 2 와 동시에)
- `bench/` 에 **에이전트형 문항** 추가: 여러 도구를 거쳐야 끝나는 과제 12개 안팎
  (예: 「이번 주 멈춘 업무 담당자별로 정리해 주간보고 초안」, 「○○ 견적 업무 만들고 담당 지정」, 「특허 진행 현황 표로 xlsx」)
- 축: Gemini(3.6 flash · lite) · Claude(Haiku · Sonnet) · (선택) OpenAI 호환. 지표: 과제 완수율 · 쓰기 정확도 · 턴 수 · **건당 원** · 지연
- 산출: `mydocs/working/…-agent-bench.md` 에 **「하루 N건 × 건당 원 = 월 예산」 표** — 회사에 요구할 금액의 근거
- 테스트 비용은 개인 부담이라 **돌리기 전에 예상 비용을 알리고 승인받는다**

### 0-b. 라우터 실험 — Jev 로 과제를 나눠 모델을 고른다 (작업지시자 요청 2026-10-28)
- Jev(TypeSafe 의 결정 전용 모델)가 요청을 분류하고, 코드가 그 결과로 모델 등급(싼 luna / 강한 sol)을 고른다. 확신이 낮으면 강한 쪽
- **상한(0단계 결과로 계산, 비용 0):** 과제마다 통과하는 가장 싼 모델을 골랐다고 치면 luna/sol 두 등급으로 건당 15.2원 → 5.6원(−63%), 완수율 100% 유지.
  하루 50건이면 월 약 1.7만 → 0.6만 원. 실제 라우터는 이보다 덜 아낀다
- 실험: `bench/agent` 에 라우터 모드를 더해 같은 13과제 × 2회. 비교 대상 = 전부 sol
- 지표: 완수율 · 건당 원(Jev 호출 포함) · 지연 증가 · 잘못 보낸 과제(싼 모델로 보내 실패)
- 판단 기준: 완수율이 전부-sol 보다 떨어지지 않으면서 건당 원이 30% 이상 줄면 3단계 런타임에 넣는다
- `ChatRoom` 에 `kind`(COMPANY · TASK · OMNIS_DM · GROUP) · `createdById` 추가, `ChatRoomMember` 표 신설
- 옴니스를 작성자로 쓰기 위한 시스템 사용자(또는 `ChatMessage.authorKind`)
- 기존 「전체」 방 → COMPANY. 업무방은 표를 만들지 않고 `taskId` 로 묶인 글을 방처럼 보여 준다
- 운영 마이그레이션은 **migrate 먼저 · 머지 나중**

### 2. 첫 화면 = 메신저 (읽기 에이전트로 먼저 연다)
- `/` → 메신저. 왼쪽 방 목록(옴니스 1:1 · 단톡 · 전사 · 업무방, 최근 순), 가운데 대화, 「새 대화」
- 옴니스 1:1 방은 지금의 읽기 도구로 **여러 턴 대화**(방의 이전 글을 문맥으로)
- 오른쪽 패널의 「Omnis AI」 탭은 이 방으로 옮기고 정리
- 여기까지로 「첫 화면 = 옴니스와의 대화」는 쓸 수 있게 된다
- **떠 있는 nav 위에 얹는다** (`feat/floating-nav`, 계획 `2026-10-28-floating-nav.md`, 머지 순서 캘린더 → nav → 채팅).
  사이드바가 없어지고 탭은 채팅(/) · 업무 · 캘린더 · 아카이브 · 마이다
  - 높이는 `MainWithChat` 스크롤 칸 안에서 `h-full`. 셸이 `--nav-offset-top`(PC 60px) · `--nav-offset-bottom`(폰 68px + safe-area)을
    이미 비워 두므로 화면 안에서 nav 높이를 빼지 않는다. 화면 전체를 덮는 fixed 요소만 두 변수를 직접 뺀다
  - 메신저가 `/` 에 들어오면 `components/layout/floating-nav.tsx` 의 `CHAT_HOME_READY` 를 true 로. 방 경로를 따로 두면 `TABS` 의 chat match 에 접두사를 더한다
  - 온보딩 투어의 "ai" 단계는 nav 채팅 탭을 가리킨다
  - 방 목록은 사이드바 자리가 아니라 **채팅 화면 안의 왼쪽 칸**이다

### 3. 에이전트 런타임 · 확인 흐름
- `AgentRun` · `AgentStep` 표, 위 실행 모델, SSE 중계, 실행당 턴 · 원 상한
- **모델 갈아 끼우기:** 벤더 어댑터(Anthropic · Gemini · OpenAI)를 `bench/agent/drivers.ts` 에서 운영 코드로 올리고,
  기능별(에이전트 · 카드 생성 · 임베딩 …) 모델을 설정 한 곳에서 바꾼다. 바꾸기 전 `bench/agent` 를 같은 과제로 다시 돌려 비교한다
- **사용량 기록을 벤더 중립으로:** `GeminiUsage` → 벤더 · 모델 · 캐시 입력 · 원 환산까지 남기는 표. 월 청구 추정과 회사 보고가 여기서 나온다
- **정기 벤치:** 새 모델이 나오거나 분기마다 과제를 갱신해 3사를 다시 잰다(1회 약 1만 원)
- 도구 위험 등급표, 쓰기 제안 카드([확인] · [고치기] · [취소]), 계획 해시 · 1회 승인
- 쓰기 도구 1차: 업무 생성 · 수정, 업무방에 지시 남기기, 지식 카드, 회사 기록
- **비밀 옮김 막기:** 쓰기 제안의 본문에 비밀번호 · 인증 정보 · 개인 식별번호가 들어 있으면 실행하지 않고 확인 카드에 이유를 보인다(모델과 무관한 코드 검사 + 시스템 프롬프트 규칙). 0단계에서 Flash-Lite 가 비밀번호를 카드에 넣으려 했다
- 런타임: AI SDK 7 `WorkflowAgent` + `needsApproval`. 정확한 API 는 설치한 패키지의 `node_modules/ai/docs/` 로 확인한다. 버전은 고정한다. 로컬은 Workflow Local World

### 4. 결과물
- 문서 초안: 주간보고 · 보고서 · 메일 회신 (방에 초안 카드로 → 확인 시 저장)
- 파일 생성: docx · xlsx · pptx 를 **Node 라이브러리로 함수 안에서** 만들고 NAS 첨부로 저장, 다시 열어 확인.
  임의 코드 실행이 필요한 일(Vercel Sandbox)은 비용을 본 뒤 따로 정한다
- 대화 → 지식: 방의 대화에서 남길 것을 기록 제안으로 올린다(지금은 업무 DONE 때만 → 채팅도 입력으로)

### 5. 단톡방 (사람끼리)
- 구성원 누구나 방을 만들고 초대한다. 옴니스는 이 단계의 단톡방에 들어가지 않는다
- 옴니스가 들어간 단톡방(`@옴니스` 로 부를 때만 응답)은 이 계획 밖 — 3단계가 자리 잡은 뒤 따로 정한다
