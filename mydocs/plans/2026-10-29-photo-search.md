# 사진도 검색되게 — 사진마다 설명글을 만들어 색인에

상태: 2026-10-29 초안. 작업지시자 검토 대기. 스키마 변경 · 운영 마이그레이션 · 벤더 비용 · 운영 DB 일괄 쓰기가
들어가 AGENTS.md 타스크 사이클 2단계(승인)를 거친다.

## 왜

옴니스 검색은 글만 찾는다. 운영 첨부 사진 1,683장(PNG 876 · JPEG 806, 2026-10-29)은 검색에 걸리지 않는다 —
카톡에서 온 사진 메시지 본문은 `Photo` 뿐이라 15자 미만으로 색인에서 빠지고(`lib/embeddings.ts` `CHAT_MIN_LENGTH`),
`File` 에는 `20260615_173422_259.png` 같은 이름뿐이다.

작업지시자가 원하는 것: **「부스 운영하는 사진 찾아줘」 「○○ 전화번호 찾아줘」 처럼 사진 안의 내용으로 찾는다.**
회사 일로 공유된 것은 모두가 빠르고 쉽게 찾게 한다.

## 실측 근거

[`working/2026-10-29-photo-describe-bench.md`](../working/2026-10-29-photo-describe-bench.md) — 6개 모델 × 사진 50장.

- 사진 없이 대화만 색인하면 운영 채팅 3,000건 사이에서 5위 안에 드는 비율 22~27%. 설명글을 붙이면 89~93%
- 검색 적중은 모델끼리 차이가 없다. 갈리는 것은 **지어냄**과 **정한 규칙을 지키는가**
- gpt-6.1-terra: 지어냄 22장 중 1건(6개 중 최소) · 시험용 민감정보 5장 규칙 5/5 · 장당 4.0원

## 작업지시자가 정한 것 (2026-10-29)

| 항목 | 결정 |
|---|---|
| 무엇을 옮기나 | 업무로 공유된 사진이다. 전화번호 · 이메일 · 계좌번호 · 비밀번호 · 와이파이 정보도 **그대로 옮겨 검색되게** 한다 |
| 가리는 것 | 주민등록번호 · 카드번호만 `[가림]`. 회사 정보가 아니라 개인 정보라서(제안 — 확인 필요) |
| 기존 사진 1,683장 | **Claude 구독**(`claude -p`, 이 맥에서)으로 한 번 돌린다. API 과금 없음 |
| 카톡 이식으로 들어오는 사진 | **Claude 구독**. 이식 도구(`import-tools/kakao.ts`)가 첨부를 붙인 뒤 같은 방식으로 설명까지 만든다 |
| 옴니스 화면 · MCP 로 올라오는 사진 | **gpt-6.1-terra** (API). 지금은 9월 25장 · 10월 1장(운영 실측 2026-10-29)이지만 **카톡에서 옴니스로 넘어오면 사진도 전부 여기로 온다.** 지금 카톡 사진 양(최근 6개월 월 평균 약 220장, 많은 달 421장) 기준 월 900~1,700원 |
| 학습 사용 | OpenAI · Anthropic 콘솔의 데이터 공유가 꺼져 있음을 작업지시자가 확인(2026-10-29) |

## 단계

### 1. 스키마 — 설명을 담을 자리

- `File` 에 `description String?`(설명 JSON 을 펼친 글) · `describedAt DateTime?` · `describedBy String?`(`openai:gpt-6.1-terra` · `claude-cli:sonnet`) 추가
- `EmbeddingSource` 에 `PHOTO` 추가. `sourceId` = `File.id`
- 마이그레이션 + Zod 스키마를 같은 커밋에(규칙 23). **운영 DB 에 먼저 적용하고 머지한다**

### 2. 설명 만들기 — `lib/photo-describe.ts`

- 입력: 사진(긴 변 1,280px 로 줄인 JPEG) + 그 메시지 앞 6 · 뒤 4 메시지 + 붙은 업무 이름. 실험 프롬프트(`prompt2`)를 그대로 쓴다
- 모델: `lib/ai-models.ts` 에 기능 `photo` 추가, 기본 `openai:gpt-6.1-terra`, reasoning low. `OMNIS_PHOTO_MODEL` 로 갈아 끼운다
- 비용: `AiUsage` 에 `feature: "photo"` 로 남긴다. 요금표에 이미 있다(`lib/ai-pricing.ts`)
- 모델이 놓쳐도 **주민번호(6-7자리) · 카드번호(16자리) 형식은 코드로 한 번 더 가린다**. 거부 사례 시험을 같이 넣는다
- 호출 시점: 이미지 `File` 이 메시지에 붙을 때(`app/api/files/route.ts` · `nas` · MCP 업로드) `after()` 로 뒤에서. 업로드 응답은 기다리지 않는다
- 실패해도 업로드는 성공. `describedAt` 이 비어 있으면 다음 일괄 실행이 줍는다

### 3. 색인 — `PHOTO` 청크

- `lib/embeddings.ts` 에 `buildPhotoChunks(fileId)`: `[사진 YYYY-MM-DD HH:mm] 올린 사람 · 업무` + 종류 · 설명 · 사진 속 글자 · 용도 · 검색어. 실험의 색인 글과 같은 꼴
- 메시지를 지우면 그 사진의 `PHOTO` 청크도 지운다(`deleteEmbeddingsSafe` 경로에 붙인다) — 사진을 지웠는데 설명이 남지 않게
- `SOURCE_LABEL.PHOTO = "사진"`

### 4. 보이기 — 검색 결과에 사진

- 옴니스 질문 · 에이전트의 출처 목록에서 `PHOTO` 는 작은 썸네일 + 그 메시지로 가는 링크
- 썸네일은 원본(평균 1.4MB)을 그대로 띄우지 않는다. `/api/files/[id]/raw?w=320` 처럼 줄여 내보내 Vercel 전송량을 아낀다
- 에이전트 비밀 옮김 막기(`lib/agent/secrets.ts`)는 그대로 둔다 — 검색 답에 비밀번호가 보이는 것은 허용(위 결정), 그것을 카드 · 기록 · 다른 방으로 **옮기는** 쓰기 제안은 지금처럼 막는다

### 5. 기존 사진 일괄 — `scripts/photo-backfill.ts`

- 이 맥에서 돈다. NAS 마운트(`~/NAS/HADD Science/옴니스 첨부파일/files`)에서 사진을 읽고 `claude -p --model sonnet` 에 넘긴다
  (`ANTHROPIC_API_KEY` 를 지워 구독으로 — 카톡 이식 도구와 같은 방식). 1장 실측 9초 → 1,683장 약 4시간, 동시 3개로 1.5시간
- `describedAt` 이 빈 것만 고른다 — 끊겨도 다시 돌리면 잇는다. `--dry` 로 대상 수만 본다
- 운영 DB 쓰기다. 로컬 스냅샷에서 50장 먼저 → 결과 확인 → 작업지시자 승인 뒤 운영
- 임베딩은 Gemini 무료 한도(하루 1,000건 수준)를 넘지 않게 나눠 넣는다
- 카톡 이식 도구의 5단계(첨부) 뒤에 「사진 설명」 단계를 붙여 **이번에 붙인 사진만** 같은 함수로 처리한다.
  이식이 쓰는 `File` 생성은 업로드 API 를 거치지 않아 2단계의 gpt 호출이 걸리지 않는다 — 그래서 카톡 사진은 구독으로만 간다.
  설명 프롬프트 · 청크 꼴은 앱과 한 곳(`lib/photo-describe.ts`)을 공유한다

### 6. 검증 · 문서

- `pnpm run verify` + 단위 시험(가림 정규식 · 청크 꼴 · 모델 선택)
- 운영에서 질의 10개(실험 질의 중 시험용 + 「부스 운영 사진」 「박○○ 전화번호」)로 실제 검색 결과 확인, 출력을 보고서에 붙인다
- `mydocs/tech/gemini-data-handling.md` 를 벤더 셋으로 넓힌다 — 사진 원본이 OpenAI(신규) · Anthropic(일괄)으로 나간다는 행, 두 회사 약관 근거

## 하지 않는 것

- 동영상(24개) — 이번에는 사진만
- 1:1 방 · 접근 통제 — 옴니스 채팅방에는 방별 권한이 없다. 사진 설명도 지금 채팅과 같은 범위(구성원 전원)에 보인다
- 사진 자체 임베딩(멀티모달 벡터) — 설명글 방식이 실측으로 충분하고, 운영 검색 경로를 하나로 둔다
