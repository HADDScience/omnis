## 구현하면서 바꾼 것

- 임베딩은 pgvector 가 아니라 `Float[]` 이다. 대조 대상이 라이브러리 100여 건 + 후보 수십 건이라 메모리에서 코사인을 재는 편이 단순하다. 라이브러리 임베딩은 `ColumnPostEmbedding` 에 캐시한다(제목+부제 해시가 바뀔 때만 다시 만든다).
- 「겹침 ⚠」 기준은 0.8 → **0.86**, 같은 주제로 합치는 기준은 **0.895** (실측 근거는 working 문서).
- 같은 주제 판정은 글자 비교만으로 안 됐다. 두 번째 수집에서 30건 중 29건이 표현만 바뀌어 새로 쌓였다. 의미 유사도로 기존 행에 근거를 합친다.

## 배경

10/13 정기회의에서 대표님이 지시했다.

- 홈페이지에 바이오 칼럼을 연재한다. 주제는 바이오 전반과 정부 지원 동향 등이고, 특정 질환·치료제에 한정하지 않는다.
- 게시 위치는 **하드:라이브러리**(뉴스 아님).
- 4명이 돌아가며 쓰기로 했지만 **순서는 아직 정해지지 않았다.** 그래서 이번에는 각자 필요할 때 쓰는 도구로 만든다.
- 흐름: 키워드 선정 → AI 초안 → 사람 검토(대표님) → 라이브러리 게시. 본문 사진에는 출처를 단다.

최종 목표는 AI 가 꾸준히 키워드를 골라 초안까지 만드는 파이프라인이다. 이번에는 **사람이 버튼을 눌러 한 번씩 돌리는 것**까지 만든다.

## 화면 흐름 (사이트 `/admin`)

관리 화면에 **「칼럼」 탭**을 하나 더 둔다(뉴스 · 하드:라이브러리 · 칼럼). 들어올 수 있는 사람은 지금 관리 화면과 같다(Omnis SSO).

```
[칼럼] ─┬─ 키워드 보드 ──────────────────────────────────────────────
        │   [후보 수집 실행]  마지막 실행 10/16 14:02 (정우창) · 후보 48건
        │   정렬: 추천순 | 최신 | 사용 이력   필터: 미사용 · 예약됨 · 사용됨 · 버림 · 내가 예약한 것
        │   ┌ 키워드 카드 ───────────────────────────────────────────┐
        │   │ 오가노이드 기반 동물대체시험 가이드라인        [정책]    │
        │   │ 설명 2줄 · 시의성: 식약처 10/14 보도자료                │
        │   │ 근거 ▸ 출처 3건(제목·매체·날짜·링크)                    │
        │   │ 겹침: 「FDA NAM 가이던스…」(3/29) 유사도 0.81 ⚠          │
        │   │ 사용 0회 · 예약: 없음                                   │
        │   │ [예약] [초안 만들기] [버리기]                           │
        │   └─────────────────────────────────────────────────────────┘
        │
        └─ 초안 목록 ─ 상태별(초안 · 검토 중 · 수정 요청 · 승인 · 게시됨), 「내 초안」 필터
              └ 초안 편집기 (기존 block-editor 재사용)
                  상단: 키워드 · 만든 사람 · 상태 · 근거 출처
                  [검토 요청] → 검토자에게 Omnis 알림
                  검토자: [승인] / [수정 요청 + 메모]
                  승인 뒤: [라이브러리에 게시] → savePost(category=library) → 영문 자동 번역
```

- 「예약」은 다른 사람이 같은 키워드로 동시에 쓰는 것을 막는 표시다. 누른 사람 이름이 카드에 남고, 그 사람이 풀거나 초안을 버리면 풀린다.
- 사진 블록은 **caption(출처)이 없으면 검토 요청 버튼이 막힌다.** AI 생성 이미지는 caption 에 "AI 생성 이미지"를 자동으로 넣는다.

## 데이터 구조 (Omnis Prisma, 새 테이블 3개)

```prisma
model ColumnKeywordRun {          // 후보 수집 한 번
  id          String   @id @default(cuid())
  startedAt   DateTime @default(now())
  finishedAt  DateTime?
  sources     Json     // 어떤 피드를 몇 건 읽었나 [{feed, fetched, ok}]
  model       String
  tokensIn    Int?
  tokensOut   Int?
  durationMs  Int?     // 한도 추적용 — 실제 함수 시간
  createdById String   // 실행 버튼을 누른 사람
  keywords    ColumnKeyword[]
}

model ColumnKeyword {
  id            String   @id @default(cuid())
  runId         String?              // 사람이 손으로 넣은 키워드는 null
  term          String               // 표시용 "오가노이드 동물대체시험 가이드라인"
  normalized    String   @unique     // 공백·기호 제거 소문자. 같은 키워드 두 번 저장 방지
  topic         String               // 정책 · 산업 · 연구 · 규제 · 투자 ...
  summary       String               // 주제 설명 2~3문장
  sources       Json                 // [{title, url, publisher, date}] — 피드에서 실제로 읽은 것만
  timelyAt      DateTime?            // 근거 중 가장 최근 날짜(시의성)
  status        String   @default("candidate") // candidate · reserved · used · discarded
  reservedById  String?              // 「예약」을 누른 사람
  reservedAt    DateTime?
  assigneeId    String?              // 로테이션용 자리. 이번 범위에서는 쓰지 않는다
  embedding     Unsupported("vector(768)")?
  nearestPostId String?              // 가장 비슷한 기존 라이브러리 글
  nearestScore  Float?               // 코사인 유사도
  createdAt     DateTime @default(now())
  drafts        ColumnDraft[]
}

model ColumnDraft {
  id          String   @id @default(cuid())
  keywordId   String
  createdById String               // 「초안 만들기」를 누른 사람 — 사용 이력의 단위
  assigneeId  String?              // 로테이션용 자리. 이번 범위에서는 쓰지 않는다
  status      String   @default("draft") // draft · in_review · changes_requested · approved · published
  title       String
  summary     String
  blocks      Json                 // 사이트 PostBlock[] 그대로 — 게시 때 변환 없음
  model       String               // 초안을 만든 모델
  durationMs  Int?
  reviewerId  String?
  reviewNote  String?
  postId      String?  @unique     // 게시된 WebsitePost id
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
}
```

- **사용 이력**은 따로 세지 않고 `ColumnDraft` 에서 센다: 사용 횟수 = 그 키워드로 게시된 초안 수, 어떤 글 = `postId`, 누가 = `createdById`.
- **기존 라이브러리 105건**은 칼럼 이전 글이라 키워드가 없다. 대신 제목+부제를 한 번 임베딩해 두고(1회성), 새 후보와의 유사도를 잰다.
- 로테이션을 붙일 때는 `assigneeId` 를 채우는 화면만 더하면 된다. 테이블은 바꾸지 않는다.

## 키워드 수집 방식 (결정 대기)

| 안 | 방법 | 비용 | 판단 |
|---|---|---|---|
| **A. 무료 피드 + Gemini 정리 (추천)** | 서버가 정해진 피드를 읽어 최근 2주 헤드라인 150~300건을 모은 뒤, Gemini 가 주제별로 묶어 키워드 30~50개를 만든다. 출처는 **모델이 쓰지 않고** 피드 항목 번호로만 가리키게 해서 URL 이 지어지지 않는다 | Gemini 토큰만(1회 수십 원 수준, 실측 필요) | 출처가 전부 실제로 읽은 기사라 검증이 쉽다 |
| B. Gemini + Google 검색 그라운딩 | 모델이 직접 검색해 키워드와 출처를 낸다 | 검색 쿼리당 별도 과금 — **현재 단가 확인 필요** | 구현은 가장 간단. 새 유료 기능이라 승인 필요 |
| C. 유료 뉴스 API | — | 월 구독 | 지금 규모에 과함. 버린다 |

A 안의 피드 후보(전부 무료):

- 뉴스: Google 뉴스 RSS 검색(바이오 · 신약 · 재생의료 · 오가노이드 · 동물대체시험 · 바이오 정부지원 등 질의어 목록)
- 정부: 식약처 · 보건복지부 · 과기정통부 · 중기부 보도자료 RSS, 한국보건산업진흥원 공지
- 공고: 기업마당(bizinfo) 지원사업 API — **API 키 발급 필요(무료)**
- 논문 동향(선택): PubMed E-utilities 최근 오가노이드·NAM 논문(무료)

정확한 피드 주소와 각 사이트의 이용 조건은 구현 첫 단계에서 하나씩 확인해 목록으로 남긴다.

```

     + 시의성(근거 최신 날짜가 가까울수록)
     − 사용 횟수 벌점
     − 다른 사람이 예약 중이면 아래로
```

- 이미 쓴 키워드와 `normalized` 가 같으면 후보에 새로 올리지 않고 기존 행의 시의성만 갱신한다.
- 유사도 0.8 이상인 기존 글이 있으면 카드에 ⚠ 와 그 글 제목을 보여 준다(숨기지 않는다 — 같은 주제를 다른 각도로 쓸 수도 있다).

## 초안 생성

- 입력: 키워드, 주제 설명, **근거 기사 본문**(서버가 출처 3~5건을 읽어 넣는다), 기존 라이브러리 글 형식 예시 1건.
- 출력: 제목 · 부제 · 본문 블록(소제목 + 문단 + 원문 링크 블록). 근거에 없는 수치는 쓰지 말라고 지시하고, 숫자마다 출처 번호를 달게 해 편집기에서 대조할 수 있게 한다.
- 모델: 기본은 Omnis 기본 모델(`gemini-3.6-flash`). 품질이 모자라면 상위 모델로 바꿀 수 있게 환경변수로 뺀다.
- 사진: 초안 단계에서는 넣지 않는다. 쓴 사람이 출처 있는 사진을 올린다. AI 인포그래픽 버튼은 결정 대기(아래 5번).

### 이 기능이 더 쓰는 양 (추정, 구현 2단계에서 실측으로 바꾼다)

가정: 수집 주 1회, 초안 월 10건, 관리 화면 API 호출 월 500회, 게시 월 4건.

| 동작 | 1회당 | 월 횟수 | Active CPU | Provisioned Memory (1 GB 함수 가정) | 호출 수 |
|---|---|---|---|---|---|
| 후보 수집 (피드 20~30개 읽기 + XML 파싱 + Gemini 1~2회 + 임베딩 50건 + DB 저장) | CPU 3~8초 · 벽시계 60~120초 | 4~5 | 약 0.5분 | 약 0.17 GB-시간 | 5 |
| 초안 생성 (출처 3~5건 읽기 + Gemini 1회) | CPU 1~3초 · 벽시계 30~60초 | 10 | 약 0.5분 | 약 0.17 GB-시간 | 10 |
| 관리 화면 API (목록·저장·상태 변경) | CPU 50~100ms | 500 | 약 0.8분 | 무시할 수준 | 500 |
| 게시 (savePost + 번역 + 사이트 재검증) | 지금 기사 저장과 같음 | 4 | 약 0.2분 | 무시할 수준 | 수십(재생성 포함) |
| **합계** | | | **약 2분 / 240분 (1% 미만)** | **약 0.4 / 360 GB-시간** | **1천 미만 / 100만** |

- Gemini 응답을 기다리는 동안은 Active CPU 로 잡히지 않지만 Provisioned Memory 로는 잡힌다(벽시계 기준). 그래서 표에 둘을 나눠 적었다.
- 사이트(haddscience) 쪽 증가는 **게시 때 재검증 1회뿐**이다. 관리 화면은 정적 셸이고 데이터는 브라우저가 Omnis 에서 직접 받는다.
- 이 추정은 크롤러 트래픽(하루 약 1.9만 요청, 10/7 커밋 `8d3e92c` 기준)에 비하면 작다. 한도 초과의 원인은 이 기능이 아니라 기존 트래픽이다.
- 실측: 수집·초안 행에 `durationMs` 를 남기고, 2단계 dry-run 뒤 위 표를 실측값으로 고친다. 실측이 추정의 3배를 넘으면 구현을 멈추고 보고한다.

### 줄이는 장치

- 수집은 버튼으로만 돈다. 자동 실행은 넣지 않는다.
- 수집 실행은 **하루 1회로 제한**한다(같은 날 다시 누르면 지난 결과를 보여 준다).
- 피드 응답은 수집 한 번 안에서만 쓰고 저장하지 않는다(DB·NAS 용량 증가 없음).

## 사이트 UX 변경 범위

- 관리 화면 상단 탭에 「칼럼」 추가. 기존 뉴스/라이브러리 탭은 손대지 않는다.
- 공개 사이트는 바꾸지 않는다(결정 4). 칼럼도 기존 라이브러리 글과 같은 모양으로 게시된다.

## 단계

1. Omnis: 테이블 3개 + 마이그레이션, 기존 라이브러리 임베딩 1회
2. Omnis: 후보 수집 API(피드 읽기 → Gemini 묶기 → 저장 · 유사도 계산) — dry-run 으로 실제 결과 30~50건 뽑아 품질과 `durationMs` 확인, 위 한도 표를 실측으로 고침
3. 사이트: 칼럼 탭 · 키워드 보드(예약 · 버리기 · 필터)
4. Omnis + 사이트: 초안 생성 · 편집 · 검토 요청 · 승인 · 게시
5. 검증: Omnis API 목킹 Playwright 로 수집→초안→게시 흐름, 운영에서는 시험 키워드 하나로 끝까지(게시 직전에서 멈춤)
