## 추천 — C, 성과목표는 2단계

이유는 셋이다.

- **셀 수 있어야 한다.** "정부지원금 총 얼마 받았나", "올해 진행중 과제 몇 건", "최근 3년 수상 실적" 은
  검색이 아니라 필터와 합계다. CRM 을 엑셀에서 모델로 옮긴 것과 같은 판단이다.
- **진짜 용도가 지원서 작성이다.** 세 시트 모두 사업계획서·지원서에 표로 반복해 붙는 자료다.
  한 곳에서 기간·기관으로 걸러 뽑을 수 있어야 값어치가 난다.
- **셋이 같은 구조다.** 전부 "시점 + 기관 + 결과" 다. 모델 셋으로 나누면 도구도 셋이 된다.
  47건짜리 자료에 그럴 이유가 없다.

카드(A)를 뺀 이유는 따로 적어 둔다. 카드가 비어 있는 것 자체가 "카드에 넣으면 안 쓰인다"는 증거다.

### 모델 초안

```prisma
// 연혁 카테고리 5종을 그대로 두지 않고, 상세 필드가 붙는 셋을 따로 뺀다.
enum RecordKind {
  GRANT        // 지원사업 (지원금·과제번호·자부담)
  AWARD        // 수상 (수상명)
  EXHIBITION   // 학회·부스 (장소·대리점)
  FORUM        // 포럼 · 세미나 참석/발표
  EDUCATION    // 교육 · 멘토링
  NETWORKING   // 네트워킹 · 방문
  INTERNAL     // 내부행사 · 입주 · 워크샵
  MILESTONE    // 그 밖의 「주요」 (설립 · 인증 취득 등)
}

model CompanyRecord {
  id         String     @id @default(uuid())
  kind       RecordKind
  title      String     // 지원사업명 · 대회명 · 학회명 · 연혁 문구
  organizer  String     // 지원기관 · 수여기관 · (학회는 빈 값 가능)
  startsOn   DateTime?  // 파싱값. 월까지만 적힌 자료는 1일로
  endsOn     DateTime?
  periodRaw  String?    // 엑셀 원문. 화면엔 이걸 보여준다 (형식이 20종이라 파싱값만 두면 뜻이 상한다)
  status     String?    // 완료 · 진행중 · 발표완료
  note       String?

  // GRANT
  subject      String?  // 과제명
  role         String?  // 주관 · 참여
  fundingKrw   BigInt?  // 원 단위로 저장한다 (엑셀은 천원)
  ownCashKrw   BigInt?
  ownInKindKrw BigInt?
  grantNo      String?  // RS-2025-…

  // AWARD
  prize      String?    // 이사장상 · 최우수상 · 본선 진출

  // EXHIBITION
  venue      String?    // 코엑스 · 가톨릭대학교
  partner    String?    // 대리점 (EAS · 오리엔트바이오 · 준바이오텍). 비면 자사

  // 연혁
  category   String?    // 엑셀 원문 카테고리 (주요 · 내부행사 · 포럼 · 교육 · 네트워킹)
  source     String     // "연혁" · "지원사업" · "수상" · "학회" — 어느 표에서 왔나. 대조에 쓴다

  projectId  String?    // 업무가 붙어 있는 과제와 잇는다. 위 표의 4건부터
  project    Project?   @relation(fields: [projectId], references: [id])
  createdAt  DateTime   @default(now())
  updatedAt  DateTime   @updatedAt

  @@index([kind, startsOn])
  @@index([startsOn])
}
```

빈 칸이 많은 한 모델과 모델 셋 사이의 맞교환이다. 47건 규모에서는 한 모델이 낫다고 본다.
`organizer` 를 `CrmOrg` 에 잇지 않는다 — CRM 의 기관은 거래처(고객)고 지원기관은 성격이 다르다.

### 이식 방법

`scripts/import-records-xlsx.ts` — `scripts/import-crm-xlsx.ts` 선례 그대로 **dry-run 이 기본, `--apply` 로 쓴다**.
돈이 걸린 자료라 같은 규칙을 따른다. 멱등은 `(kind, title, startsOn)` 기준 upsert.

손볼 것이 이미 보인다.

| 것 | 어떻게 |
|---|---|
| 지원기간 형식 20종 | 정규식 하나로 파싱하고 원문을 `periodRaw` 에 남긴다 |
| BOM(`﻿`) 2셀 · non-breaking space 2셀 | 정규화해서 넣는다 |
| 합계행(847,700) | 순번이 비어 있는 행은 건너뛴다. 합계는 저장하지 않고 셀 때 계산한다 |
| 결과 빈칸 1건(G-SUMMIT) | `status` 를 null 로 두고 보고에 적는다. 지어내지 않는다 |
| 같은 사업명 2행 (메디바이오 2차 — 경과원 / 대구TP) | 기관이 다르니 별개 행. upsert 키에 `organizer` 를 넣는다 |
| 자부담금 빈칸 vs 0 | 빈칸은 null, 0은 0 |
| 대리점 표 빈 행 2개(결과만 '완료') | 학회명이 비면 건너뛴다 |
| 연혁 날짜 빈칸 2행(`날짜필요`) | `startsOn` null 로 넣고 보고에 적는다. 지어내지 않는다 |
| 연혁 ↔ 다른 시트 날짜 불일치 | 시트를 정본으로. 대조표를 찍어 작업지시자가 확인한다 |
| 연혁의 특허·상표 출원 행 | 저장하지 않는다 (`ip` 스키마가 정본) |

### 노출

- **도구 하나** — `list_records(kind?, year?, status?, query?)`. 옴니스 질문과 MCP 양쪽에 붙는다.
  이게 있어야 "우리 정부과제 실적" 을 AI 가 센다.
- **화면 하나** — HADD DB(`/omnis`) 아래 「회사 실적」. 카드가 비어 있어 HADD DB 랜딩이 지금 허전하기도 하다.
- 임베딩은 넣지 않는다. 세는 자료라 검색이 아니라 조회로 답해야 한다 (9-09 벤치 결론).

### 검증

- 이식 뒤 합계가 847,700천원과 맞는지, 건수 24 · 9 · 14 · 연혁 136 이 맞는지 스크립트가 스스로 확인한다.
- 겹치는 행을 합친 결과를 대조표로 찍는다 (몇 건이 합쳐졌고 어느 날짜를 골랐는지).
- 벤치 질문에 집계 문항을 더한다 — "정부지원금 총액", "올해 진행중 과제", "작년 수상 실적".
- `tests/scenario/full.spec.ts` 질문 파일에도 같은 문항을 더해 회귀로 잡는다.

## 2단계 — 성과목표 (이번에는 안 한다)

26성과목표 시트는 알맹이가 상단 취합본(8항목 × 3과제)이고, 나머지는 서술형 추진내용과 121열짜리 월별 간트다.
간트까지 옮기는 것은 값어치보다 품이 크다.

값어치가 나는 지점은 따로 있다. **목표 대비 실적을 자동으로 세는 것**이다 —
특허 출원은 `ip.cases`, 학술대회 발표는 이번에 넣을 `CompanyRecord(EXHIBITION)`, 채용은 `User` 에 이미 있다.
목표치만 모델로 올리면 "디딤돌 특허 2건 중 몇 건 했나" 를 계산할 수 있다.
설계가 커지므로 1단계가 실사용에 오른 뒤 따로 정한다.

## 먼저 확인할 것 (작업지시자)

1. **선택지 C 가 맞는지.** B(Project 확장)를 고르면 업무 연결이 공짜인 대신 프로젝트 목록이 더 지저분해진다.
2. **금액을 원 단위로 저장**하는 것이 맞는지 (엑셀은 천원 단위. CRM 은 원 단위를 쓴다).
3. 엑셀이 앞으로도 원본인지, 아니면 이식 뒤 옴니스가 원본이 되는지. 후자면 화면에 편집이 필요하다.
