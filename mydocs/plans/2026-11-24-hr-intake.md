# 채용(HR) 1단계 — 홈페이지 지원서 접수 창구

작업지시자 요청(2026-11-24). 홈페이지 Career 탭(hadd-website `app/api/career/apply`)의 지원서를 옴니스가 받는다.
설계는 작업 보고서 `omnis-hr-design-261124.md`, 홈페이지와의 계약은 `omnis-hr-api-contract-261124.md`(둘 다 `~/work/omnis-reports/`)다.

## 정한 것 (작업지시자 확정)

| # | 결정 |
|---|---|
| D1 | 파일은 옴니스 조각 업로드(4,000,000바이트 이하) → NAS 이어 쓰기(`lib/storage.ts putRangeAt`). Blob · R2 를 새로 쓰지 않는다 |
| D2 | 채용 담당 = 대표 + 현장실습 담당. `AppSetting hr_reviewers` — 관리자라도 고르지 않으면 못 본다. 비면 아무도 못 본다 |
| D3 | 파기 = 담당이 「선발 종료」 + 6개월, 누르지 않으면 접수 + 12개월(1단계는 접수 때 12개월로 찍고, 선발 종료는 2단계) |
| D4 · D7 | 결과 안내는 손으로, 메일 되돌림은 `info@` 그대로 |
| D5 | `StaffProfile` 구분 칸(INTERN)은 3단계(입사 → 인력 현황) |
| D6 | 새 지원서 알림은 벨 · 푸시만. 이름 · 연락처를 싣지 않는다 |
| D8 | 도구 `list_applications` — 담당만, 단계 · 건수 · 이름 · 학과 · 학년까지. 연락처 · 동기 · 파일은 AI 에 보내지 않는다 |
| D10 | 이번 공고(마감 2026-11-27 17:00 KST)는 메일 되돌림으로 받는다 |

## 단계

1. 스키마 · 마이그레이션 — 새 표 셋(`JobApplication` · `JobApplicationFile` · `JobApplicationEvent`) · enum 둘. 기존 표는 칸을 바꾸지 않는다
2. 입구 셋 — `POST /api/website/applications`(비밀) · `PUT …/[id]/files/[slot]?part=n`(티켓 · CORS) · `POST …/[id]/complete`(비밀). 규칙은 `lib/hr/rules.ts`, 처리는 `lib/hr/intake.ts`
3. 지원서함 — `/hr/applications`(목록) · `/hr/applications/[id]`(상세 · 열람 기록) · 파일 내려받기(기록) · 관리자 › 운영의 채용 담당 · 마이 입구
4. 알림 · 파기 — `job_application`(담당) · `job_application_unassigned`(담당이 없을 때 관리자, 하루 한 번) · `cron/daily` 의 `runHrUpkeep`
5. 시험 — `lib/hr/rules.test.ts`(거부 사례 포함) · `tests/feature/hr-applications.spec.ts`(가짜 NAS 의 이어 쓰기 흉내를 더함)

## 운영 반영 순서 (작업지시자 지시 뒤)

1. Vercel `omnis-hadd` production env: `WEBSITE_CAREER_SECRET` · `WEBSITE_CAREER_UPLOAD_KEY` (`WEBSITE_CAREER_ORIGINS` 는 기본값이면 두지 않는다). NAS 폴더 `/HADD Science/08. 개인정보/옴니스 채용 지원서` 를 만들고 DSM 권한을 채용 담당으로 좁힌다
2. 운영 DB `pnpm run db:deploy`(이 브랜치 워크트리에서) → 머지 → 배포
3. 관리자 › 운영 › 채용 담당에서 두 사람을 고른다
4. 홈페이지 `CAREER_SECRET`(운영에만) · `deliver()` · 폼 업로드 · 동의문 · 방침 개정(hadd-career)
5. 운영에서 시험 지원 1건 → 확인 → 지운다(2단계 「지금 파기」 전에는 DB · NAS 에서 손으로 지운다 — 운영 쓰기라 승인 필요)
