# 미배정 업무 상세에서 바로 담당 지정

작업지시자 요청(2026-11-09). 담당이 빈 업무를 열면 위쪽에 「담당자가 없어요」 칸이 뜨고, 이름 칩을 한 번 누르면 그 사람이 담당이 된다.

## 정한 것

- **언제 뜨나**: 미완료이면서 담당 0명(`lib/task-unassigned.ts` 의 기준 그대로). 담당 편집을 연 동안은 숨긴다.
- **누구를 보이나**: 담당 후보(재직자)만. 과거 구성원은 서버가 새 담당으로 받지 않으니 칩에서 뺀다.
- **몇 명**: 칩 하나 = 한 사람 지정. 데이터 모델은 여러 명을 허용하므로, 더 붙일 사람은 지정 뒤 담당 옆 연필로 더한다.
- **검색**: 고를 사람이 12명을 넘을 때만 이름 검색이 뜬다. 지금 인원이면 칩만 보인다.
- **저장**: 기존 `PATCH /api/tasks/[id]` 의 `assigneeIds` — 권한 · 담당 지정 알림 · 이력은 `lib/task-update.ts` 가 그대로 낸다.
- **낙관적 갱신**: 누르는 즉시 칸이 사라지고 담당 표시가 바뀐다. 저장이 실패하면 담당을 되돌리고 칸이 다시 뜨며 오류 알림을 띄운다.
- **크기**: 폰은 칩 높이 44px(엄지), md 이상은 32px 로 카드 사이 한 줄에 붙는다. 폰은 루트 글자 크기가 작아 `min-h-11`(rem)이 36px 로 줄어든다 — px 로 고정한다.

## 시험

- 단위: `lib/quick-assign.test.ts` — 칸을 띄우는 조건, 과거 구성원 제외, 검색.
- e2e: `tests/feature/quick-assign.spec.ts` — PC 지정 · 새로고침 뒤 칸 없음, 저장 실패 시 되돌림, 폰 칩 44px, 완료 업무는 칸 없음.
  API 는 담당 없는 업무를 만들지 않아 DB 에 직접 넣는다 — 격리된 시험 DB(`pnpm run test:e2e:local`)에서만 돈다.
