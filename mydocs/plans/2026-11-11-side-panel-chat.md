# PC 오른쪽 패널 = 폰 채팅 탭

작업지시자 요청(2026-11-11).

## 1. 동작

- 패널 속은 폰 채팅 탭 그대로다 — 방 목록(칩 · 검색 · 줄) → 방 → 대화, ← 로 목록. 예전 「전체」(전사 채팅) · 「옴니스」(드롭다운으로 고르던 옴니스 1:1) 탭은 목록의 방 하나씩이 됐다.
  - 새 옴니스 대화는 목록 오른쪽 아래 「새 대화 → 옴니스와 대화」. 「사람과 대화」 는 본문의 사람 고르기 화면으로 간다.
  - 업무 상세에서 열면 「이 업무」(그 업무 스레드) 탭이 앞에 하나 더 있다 — 지금과 같다.
- 방을 옮겨도 본문 주소는 그대로다. 업무 · 캘린더 · 아카이브 화면을 옆에 둔 채 채팅한다.
- nav 「채팅」 — 패널을 연 채 누르면 패널에서 마지막으로 보던 방이 본문에 열리고 패널은 닫힌다. 패널이 닫혀 있으면 지금처럼 목록.
  채팅 화면(/chat…)으로 들어오는 다른 길(「크게 보기」 · 링크)로 와도 패널은 닫힌다.
- 패널을 다시 열면 마지막으로 연 방이 열린다(기기에 사람마다 저장, `omnis.panel.room.<사람 id>`). ← 로 목록에 가도 기억은 남는다.
- ⌘⇧F 는 패널을 열고 전사방의 검색 줄로 간다(예전 「전체」 의 검색과 같은 검색). ?taskId= 링크는 패널의 그 업무방을 연다.

## 2. 구조 — 복사하지 않고 같은 부품

- `components/layout/panel-messenger.tsx` 가 메신저 부품을 그대로 쓴다: `RoomList` · `ClientRoom`(전사 · 사람 방) · `TaskRoom`(업무방, 페이지와 같이 쓰도록 뺐다) · `OmnisRoom`(`PanelOmnis` 가 감싼다).
  루트에 `data-messenger` 를 달아 크기도 폰 채팅 탭과 같다(패널 400px ≈ 폰 폭).
- 메신저 부품은 주소로 방을 안다. 패널에서는 `PanelNav` 맥락(messenger-context.tsx)이 대신한다 — 있으면 목록 줄 누르기 · 뒤로 단추 · 볼 수 없는 방 · 방 나가기가 주소 대신 그것을 쓴다. 없으면(/chat) 지금 그대로다.
- 업무방은 서버 페이지가 글을 그렸다(router.refresh). 패널은 본문이 다른 화면이라 `GET /api/chat/task-rooms/[taskId]` 로 같은 글(`lib/chat-task-room.ts`)을 받고, 보낸 뒤 · 10초마다 다시 받는다. `TaskThread` · `ThreadComposer` 에 `onChanged` / `onSent` 를 주면 router.refresh 대신 그것만 부른다.
- 레이아웃이 페이지마다 패널용 전사방 글 50개를 읽던 쿼리는 지웠다(패널이 방을 열 때 읽는다).
- 순수 규칙: `lib/panel-chat-rules.ts`(방 주소 · 기억한 방 검증 · 채팅 탭이 갈 곳 · 패널 닫기).

## 3. 시험

- 단위: `lib/panel-chat-rules.test.ts`.
- e2e: `tests/feature/side-panel-chat.spec.ts` — PC 1440 · 1280(목록 → 방 → ←, 본문 주소 유지, 넓은 표 · 긴 주소 넘침 없음, 새 옴니스 대화), 채팅 탭 넘기기 · 다시 열기, ?taskId=, 폰 채팅 탭 그대로.
- 패널을 열면 전사방 입력창이 바로 보인다고 가정한 기존 시험(\_actions · \_setup · 단축키 · iPad · 입력창 · 검색 도착 · 업무 시작)은 목록에서 전사방으로 들어가게 고쳤다.
