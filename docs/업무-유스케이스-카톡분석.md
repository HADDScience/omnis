> 대상: 하드사이언스 인턴방 · HADD-수원대방 · 윤훈 상무 1:1
> 기간: 2025-08-20 ~ 2026-06-12 (10개월)
> 규모: **메시지 9,214건 · 세션 633개(전수) · 구성원 8명 · 지시 781건**
> 방법: 시간 기반 세션 분할(60분 공백) → **Claude Haiku 서브에이전트 전수 분류**.

> 원자료: `analysis/data/merged.json` (633세션 분류 결과)

## UC-1. 담당자 미정 지시가 다수 (68%)

지시 781건의 담당자 결정 방식이다.

| 방식 | 건수 | 비율 | 뜻 |
|---|---|---|---|
| **미정** | 530 | **68%** | 누가 할지 정해지지 않음 |
| 맥락 | 172 | 22% | 이름은 없지만 흐름상 담당자가 분명 |
| 명시 | 73 | 9% | 이름을 직접 호명 |

이름을 직접 부르는 경우는 **9%뿐**이다. 나머지 91%는 맥락에 기대거나 아예 미정이다.

**설계 함의** — 이 셋은 UI가 서로 달라야 한다.

- **명시(9%)**: 담당자를 그대로 채워 넣으면 된다.
- **맥락(22%)**: AI가 추론해 **제안**하고 사람이 확인한다. 자동 확정은 위험하다.
- **미정(68%)**: 담당자 없이 업무가 만들어져야 한다. **`미배정` 상태와 "제가 하겠습니다" 수령(claim) 흐름**이 필요하다.

현재 `app/api/tasks/route.ts`는 `ownerId`가 없으면 400으로 거절한다.
**지시의 68%를 업무로 만들 수 없는 구조다.**

## UC-2. 한 세션이 여러 업무로 쪼개진다

```
지시가 포함된 세션        279개
그중 지시 2건 이상        149개 (53%)
한 세션 최다 지시         18건
프로젝트 2개 이상 걸친 세션  73개 (12%)
```

**설계 함의**: 세션·메시지를 업무 카드와 1:1로 매핑할 수 없다.
구조화 결과를 **여러 업무로 분할**하는 단계가 반드시 있어야 한다.
"업무 생성" 버튼 하나로 카드 1개를 만드는 현재 흐름으로는 절반이 표현되지 않는다.

## UC-3. 즉답 문화 (중앙값 2.1분)

```
지시 → 첫 응답  중앙값 2.1분 · 평균 8.8분 · 90%ile 30.4분
5분 이내 응답   68%
같은 세션 내 무응답 11%
```

**설계 함의**: 카톡은 2분 안에 반응이 온다. Omnis는 여기에 LLM 3~8초와
초안 검토·생성 클릭을 얹는다. **느려서 안 쓰게 되는 것이 가장 현실적인 실패 시나리오다.**
지시 입력은 카톡만큼 빨라야 하고, 구조화는 뒤에서 비동기로 붙어야 한다.

## UC-4. 완료가 그 자리에서 닫히지 않는다

| 대상 | 세션 내 완료 |
|---|---|
| 전체 지시 781건 | 158건 (20%) |
| 담당자가 지정된 지시 251건 | 96건 (38%) |

담당자가 정해진 지시조차 **62%는 그 세션에서 완료되지 않는다.**
지시와 완료가 대개 다른 세션에서 일어난다는 뜻이다.

**설계 함의**: 업무 종료를 대화에서 자동 추론하는 것은 근거가 약하다.
`rebuildTask`가 AI 판단으로 `status: DONE` + 체크리스트 전체 완료 처리를 하는 현재 구조는
위험하다. 완료는 **사람이 누르는 명시적 행위**여야 하고,
대신 오래 열린 업무에 리마인드가 필요하다.

## UC-5. 파일이 산출물 제출 수단

```
미디어·파일  1,656건 (전체의 18%)
발신자       김아리 391 · 정우창 359 · 허채정 294 · 노혜린 220 · 박소정 210
파일 전송 직후 피드백·추가지시  19%
```

업무의 실체가 파일로 오가고 그 위에서 검토 루프가 돈다.

**설계 함의**: `app/api/files/route.ts`는 로컬 파일시스템에 쓴다(`writeFile`).
**Vercel 서버리스에서는 EROFS로 100% 실패한다.**
첨부가 안 되면 이 워크플로가 Omnis로 넘어오지 못한다. 데이터 이식보다 우선순위가 높다.

## UC-6. 지시·수행이 소수에게 집중

**지시자** (781건 기준)

| 구성원 | 직급 | 지시 |
|---|---|---|
| 김아리 | 팀장 | 265 |
| 노혜린 | 과장 | 220 |
| 정우창 | 사원 | 125 |
| 허채정 | 대표 | 78 |
| 박소정 | 인턴 | 76 |
| 윤훈 | 상무 | 11 |

**주요 지시 흐름** (지시자 → 담당자)

```
37  노혜린 → 정우창      17  노혜린 → 박소정
36  김아리 → 정우창      13  노혜린 → 주용석
19  정우창 → 김아리      11  김아리 → 박소정
```

김아리·노혜린 두 사람이 전체 지시의 **62%**를 낸다. 대표·상무는 오히려 적다.
`정우창 → 김아리`가 19건인 것처럼 **역방향 지시도 존재**한다.

**설계 함의**: 위계 기반 권한(`ADMIN`/`MEMBER`)으로는 실제 흐름이 표현되지 않는다.
지시는 직급이 아니라 **업무 맥락**에서 나온다.
(사용자가 "롤 말고 직급만 표시"를 요청한 것과 일치하는 결과)

## UC-7. 오후 집중

```
업무시간(09~18시) 89%  ·  주말 1%
피크  15시(118) · 17시(104) · 16시(88) · 14시(77)
```

**설계 함의**: Gemini 하루 20회 한도는 **오후 2~3시간에 소진된다.**
배치 처리·쿼터 정책은 이 피크를 기준으로 설계해야 한다.

## 방법론과 한계

- **분류 주체**: Claude Haiku 서브에이전트 9개가 633세션을 전수 처리했다. Gemini는 쓰지 않았다
  (무료 티어 하루 20요청 제약 때문).
- **교차 검증**: 규칙 기반(정규식) 분석을 병행했고 담당자 미지정 비율은 규칙 74% / LLM 68%로
  근접했다. 반면 완료율은 규칙 기준(윈도우 의존 14~60%)이 불안정해 LLM 판정을 채택했다.
- **부분 표본의 위험**: 청크가 시간순이라 중간 집계(415세션 시점)에서 지시자 순위가 뒤바뀌어
  보였다. **전수 집계 전 수치는 신뢰할 수 없다**는 교훈.
- 담당자 "맥락" 판정은 LLM의 해석이며 사람 검수를 거치지 않았다.
- 파일·사진의 **내용은 export에 없다**. 산출물의 성격은 분석 불가.
- export가 2026-06-12에서 끊긴다. 이후 약 3개월은 미반영.
- `assignee_basis`에 스키마 외 값(`manifest`) 6건이 섞여 있다(0.8%, 무시 가능).
