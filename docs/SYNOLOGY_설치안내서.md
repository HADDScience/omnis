# Omnis 설치 안내서 (NAS 설치 담당자용)

> 이 문서 하나로 설치가 끝나도록 만들었습니다. **명령어 입력은 없습니다.**
> DSM 화면에서 마우스로만 진행합니다. 예상 소요: **15~20분**

---

## 1. 한 장 요약

| 항목 | 내용 |
|------|------|
| **무엇** | Omnis — 채팅 한 줄로 업무가 등록되는 사내 업무관리 시스템 |
| **어디에** | Synology NAS (DS1621+)의 Container Manager |
| **필요 권한** | DSM 관리자 그룹 (Container Manager 사용 권한) |
| **설치 형태** | 독립 컨테이너 2개 (앱 1 + 전용 DB 1) |
| **NAS 자원 사용** | 최대 CPU 2코어 · 메모리 2GB (상한을 파일에 고정해 둠) |
| **여는 포트** | 1개 (기본 3000번, 충돌 시 변경 가능) |
| **되돌리기** | Container Manager에서 프로젝트 삭제 1회 — 흔적 없이 원복 |

## 2. 공동 사용 NAS에 미치는 영향 (검토용)

이 NAS를 다른 회사와 함께 사용하고 있어, **기존 서비스에 영향이 없도록** 다음을 설정 파일에 못 박아 두었습니다.

| 우려 사항 | 조치 |
|-----------|------|
| NAS 자원을 독점하지 않나? | CPU 2코어 · 메모리 2GB **상한을 설정 파일에 명시**. 초과 불가 |
| 기존 서비스와 포트가 겹치지 않나? | 외부에 여는 포트는 **단 1개**. 겹치면 설정값 한 줄만 변경 |
| 다른 컨테이너에 접근하지 않나? | **전용 네트워크(`omnis_net`)** 안에서만 통신. 외부 컨테이너와 격리 |
| 데이터베이스가 노출되지 않나? | DB는 **포트를 열지 않음**. 앱 컨테이너에서만 접근 가능 |
| NAS의 기존 파일을 건드리지 않나? | 지정한 설치 폴더 외에는 **접근하지 않음** |
| 문제가 생기면 되돌릴 수 있나? | 프로젝트 삭제 한 번으로 완전 제거 |

> 관리자께서 추가 확인을 원하시면 `docker-compose.yml` 파일을 직접 열어보시면 됩니다.
> 위 내용이 모두 주석으로 적혀 있습니다.

---

## 3. 준비물 (설치 전 확인)

정우창이 전달한 **`omnis-설치패키지`** 폴더 안에 다음이 들어 있습니다.

```
omnis-설치패키지/
├── docker-compose.yml     ← 설정 파일 (수정 불필요)
├── .env                   ← 비밀번호·키가 이미 채워져 있음 (수정 불필요)
└── images/                ← [B안일 때만] 이미지 파일 2개
```

> ⚠️ `.env` 파일에는 **비밀번호가 들어 있습니다.** 메신저 공개 대화방이 아닌
> 직접 전달 또는 비밀번호 걸린 압축으로 받아 주세요.

**설치 전 한 가지만 확인**해 주세요.

- NAS에서 **3000번 포트**를 이미 쓰고 있는지
  - 확인: DSM → 제어판 → 로그인 포털 → 고급 → 리버스 프록시 목록
  - 쓰고 있다면 정우창에게 알려주시면 다른 번호로 바꿔 다시 전달드립니다.

## 4. 설치 절차

### 4-1. 설치 폴더 만들기

1. DSM 로그인 → **File Station** 열기
2. 원하는 위치(예: `docker` 공유폴더)에 **`omnis`** 폴더 생성
3. 전달받은 파일 **전부**를 이 폴더에 업로드
   - `docker-compose.yml`
   - `.env`
   - (B안일 때) `images` 폴더

> `.env`는 점(`.`)으로 시작해서 File Station에서 안 보일 수 있습니다.
> 보기 → **숨김 파일 표시**를 켜면 확인됩니다.

### 4-2. [B안일 때만] 이미지 먼저 불러오기

> NAS가 인터넷에서 프로그램을 내려받을 수 없는 환경일 때만 해당합니다.
> **A안(인터넷 가능)이면 이 단계를 건너뛰고 4-3으로 갑니다.**

1. **Container Manager** 실행 → 좌측 **이미지**
2. **추가 → 파일에서 이미지 추가**
3. `images/omnis.tar.gz` 선택 → 완료까지 대기 (2~3분)
4. **같은 방법으로 `images/pgvector.tar.gz`도 추가** ← 빠뜨리면 실행되지 않습니다
5. 이미지 목록에 2개가 보이면 성공

### 4-3. 프로젝트 생성 (핵심 단계)

1. **Container Manager** → 좌측 **프로젝트** → **생성**
2. 입력값
   - **프로젝트 이름**: `omnis`
   - **경로**: 4-1에서 만든 `omnis` 폴더 선택
   - **소스**: "기존 docker-compose.yml 사용" 선택
     → 폴더 안의 파일을 자동으로 인식합니다
3. **다음** → 웹 포털 설정 화면은 **건너뛰기**
4. **완료** → "빌드 후 컨테이너 시작" 체크 상태로 진행

A안(인터넷 가능)이면 이 시점에 프로그램을 자동으로 내려받습니다. **3~5분** 걸립니다.

### 4-4. 정상 동작 확인

프로젝트 화면에 컨테이너 **2개**가 **실행 중(초록색)**으로 보이면 성공입니다.

- `omnis-db` — 데이터베이스
- `omnis` — 앱

> `omnis`가 잠깐 재시작되는 것은 정상입니다. DB 준비를 기다린 뒤 자동으로 붙습니다.
> **2분 이상** 계속 재시작되면 6번(문제 발생 시)을 봐 주세요.

## 5. 접속 및 첫 로그인

1. NAS 내부 IP 확인: DSM → 제어판 → 네트워크 → 네트워크 인터페이스 (예: `192.168.0.10`)
2. 브라우저 주소창에 입력: **`http://<NAS내부IP>:3000`**
3. 로그인
   - **아이디**: `김아리`
   - **비밀번호**: 정우창이 별도로 알려드린 초기 비밀번호

대시보드가 보이면 **설치 완료**입니다.

> 최초 실행 시 기본 계정과 기본 데이터가 자동으로 만들어집니다.
> 별도 명령을 입력하실 필요가 없습니다.

### 설치 후 (정우창이 진행)

- 실제 팀원 계정 생성 및 초기 비밀번호 변경 안내
- 필요 시 외부 접속용 리버스 프록시 요청 (아래 7번)

## 6. 문제 발생 시

무엇을 하셔도 **NAS의 다른 서비스에는 영향이 없습니다.** 편하게 확인해 주세요.

| 증상 | 확인 방법 |
|------|-----------|
| 컨테이너가 계속 재시작됨 | Container Manager → 컨테이너 → `omnis` → **로그** 탭 캡처해서 전달 |
| 페이지가 안 열림 | 컨테이너 2개가 초록색인지 확인 → 포트 번호 확인 |
| "포트가 이미 사용 중" 오류 | 3000번 충돌. 정우창에게 알려주시면 파일 교체해 드립니다 |
| 이미지를 못 받아옴 (A안) | NAS 인터넷 차단 상태. B안(이미지 파일 방식)으로 전환 필요 |

**가장 도움이 되는 것**: Container Manager → 컨테이너 → `omnis` → **로그** 탭 화면 캡처
이것만 보내주시면 대부분 원인을 바로 찾을 수 있습니다.

### 완전히 되돌리기

Container Manager → 프로젝트 → `omnis` → **작업 → 삭제**
컨테이너·데이터가 모두 제거되고 NAS는 설치 전 상태로 돌아갑니다.

---

## 7. (선택) 사외에서 접속하려면

사내 LAN 밖에서도 쓰려면 리버스 프록시 1건이 필요합니다.

> DSM → 제어판 → 로그인 포털 → 고급 → **리버스 프록시** → 생성
> - 소스: `https://omnis.<회사도메인>` (포트 443)
> - 목적지: `http://localhost:3000`

추가 후 정우창에게 알려주시면 설정값을 맞춰 드립니다.
**사내에서만 쓸 계획이면 이 단계는 불필요합니다.**
